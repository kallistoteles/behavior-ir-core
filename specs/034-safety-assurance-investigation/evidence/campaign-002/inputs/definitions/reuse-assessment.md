# Primary results and reuse boundaries

The [origin register](requirement-origins.json) distinguishes checking a program from checking its executed prefix. No new proof backend is selected here. Source identities are in [the catalogue](inputs/source-catalog.json); exact passages are in [the contexts](inputs/source-contexts.json). Reading pinned bytes is not a new kernel check.

| Contribution | Reusable method and premises | Core connection and remaining gap |
| --- | --- | --- |
| Safety 510 FieldOwnership / LifecycleDependency | Generic preservation plus concrete exact-module/action/operation coverage, checked guards, projection and Core-condition premises. A valid initial state and enforced allowed transitions permit induction over an actual deployment segment. | Keep existing public analysis, certificate checking and snapshot validation. Extractor correctness, actual Rust execution correspondence, complete snapshot/export and every-writer control are separate premises; a certificate cannot prove that the host obeyed it. |
| Safety 511 independent checking | Treat producer witnesses as untrusted; independently establish exact inventory/binding, intended statements, transitive axiom allowlist and fresh kernel replay. Charge complete construction and checking chains separately. | Reuse the actual pinned public Safety verifier. A fresh program evidence checker is not automatically a replay-free verifier of runtime history. Kernel replay is not a separately implemented kernel. |
| Core 032 abstract State/Checker/History/Observation results | Independently checked exact observations compose from an accepted origin; established prefix plus checked suffix supports continuation. State/identity/query coverage and observational equality remain explicit. | Adapt only reachable pinned small proofs into the new assurance model. These abstract results do not verify the complete native Core, extraction, original hashing, storage, or a cryptographic circuit. |
| Core 031 measurements and verification discipline | Distinguish full observations from equal endpoints, logical output size from processing volume, replay availability from proof validity, and snapshots from original provenance. | Preserve original bytes/IDs and use public replay for B. Historical benchmark numbers remain scoped old measurements, not an LD8 A/B comparison. |
| Core 033 feasibility evidence | Identity/backend diagnostics and actual stopped initialized-prefix attempts expose construction cost and correspondence gaps. Negative evidence is reusable under its exact subject and limits. | Do not rerun a proof without a new question, promote a toy identity proof into a Safety certificate, or infer a lower bound on every future proof architecture. C remains the unchanged strong comparator. |

The new composition proofs must use an actual imported preservation result under named correspondence premises. A theorem that merely assumes its desired post-state is not sufficient. Adjoining segments need exact boundary continuity; different policies need explicit implication into any single global property. Checking a history says nothing by itself about latest-head authority, physical command execution, or durable publication.

For the memory pilot, authoritative durable publication (Q6) remains unestablished. A known failed proof obligation cannot be relabeled trusted. Missing proof tools or resource exhaustion are operational outcomes, not semantic counterexamples. Program analysis, exact-history checking and cryptographic proof transport can be developed separately without declaring their guarantees interchangeable.
