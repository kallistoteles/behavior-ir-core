# G2 — selected global/local language

The authoritative selected eligibility classifier is in Core's prepared-state module;
Store delegates to it. It inspects every entity obligation and global root, resolving
local derived references under the admitted semantic profile. A mixed/unknown root
selects ordinary execution. The selected globals are Boolean literals and exact typed
`count(select(T)) <= K`. No action origin, name or display metadata limits the actual
World delta: the ordinary interpreter supplies every bound, created and removed entity.

The complete typed parent mapping supplies membership and O(1) per-type cardinality.
For S' with no removals, Count uses checked addition of actual fresh disjoint creates,
followed by the unchanged checked i64 conversion. It still emits exact canonical base
query membership. Unknown queries retain ordinary membership evaluation. This is not
an externally supplied count or a second persistent index.

For unchanged unbound rows, cached observer templates originate in the *same*
`run_child_row`/`run_rules` implementation used by ordinary action evaluation. Only
explicit scalar expression constructors and synthesized positive Ref rules qualify.
Derived rule observer/memo replay is deliberately not claimed: those rules continue
through ordinary child evaluation. Unsupported modules retain ordinary execution.

Templates retain success and skipped traces, exact fields, operand values and Ref
existence observations. Bound-target existence facts are suppressed exactly as
`exists_s` does. No-removal preserves existing positive references; changed and new
references use the complete simultaneous child. Bound/created rows run ordinary checks.
Preflight child identity/collision errors precede all child traces as in the reference.
Canonical parent/new-row merge preserves decoded (type,id) ordering. Templates for the
next state use the actual successful child row and its complete created-target context.
They are installed only at the exact successful Store CAS.

The old Store Candidate remains the feature-015 partial-row local-rule path; it is
never submitted to the global checker as a complete state. Selected global transitions
instead carry opaque evidence from Core's actual complete child execution. Maintaining
a second Store cardinality interpreter would duplicate authority unnecessarily.

- `g2-classifier-red.txt`: classifier absence before implementation.
- `g2-store.txt`: focused classifier, complete cycle, 1000/1001, reference, negative,

  allowed typed-key set for each operation, including the next-evaluation drain.
- Exact full-record/reference comparisons cover empty states, sequential and simultaneous
  fresh creates, three global roots, and equal textual identifiers in different types.
- The Core tests independently require DENY for violated row rules, ERROR for overflow,
  and ALLOW otherwise; exact traces/skipping/read/fact results match ordinary evaluation.

The work controls require zero full snapshot-row checks and zero typing or child-rule
checks on unrelated rows in selected steady-state operations. They separately disclose
output-sized child visits; those visits construct required normative per-row evidence.
