# US1 — Complete-path baseline

Disposition: **supported-by-evidence** for this measured profile, with the limits below.

All 32 frozen cases have three production-like repetitions and one separate diagnostic run; every observation matches the forced-full canonical reference bytes and the independent case oracle. The five required dimensions have at least three levels, including N=8192/eight creations and the combined public workload. Three release-mode durable lost-ack trials complete recovery coverage. Data, behavior and reference replay pass in all internal cases.

The main finding is retained linear evidence work after successful incremental semantic validation. The production N=8192 cycle median is 20.984 s, with commit the largest phase; this is distinct from the 91.324-s whole multi-path/audit probe. Predicates remain 53, while named child-row visits reach 139,328 and named hash JSON volume 180.150 MB. No whole-Rust complexity or CPU-allocation theorem follows from these measurements.

Review [cost-model.md](cost-model.md), [coverage](baseline/assessment.json), [raw production samples](baseline/timing-rows.jsonl), [raw diagnostic samples](baseline/diagnostic-rows.jsonl), [statistics](baseline/primary-summary.json), [portable exact observations/source](portable/index.json), [recovery](baseline/recovery-release.json), [gates](baseline/gates.txt) and [lineage](baseline/lineage.json). The 120-second preparation timeout is retained; all mandatory coverage succeeds under the declared 300-second profile. No slow repetition was replaced.

The ordinary probe uses the reference in-memory backend. Memory includes audit retention; cold reopen clears Store caches rather than every backend index; durable recovery covers a small local fixture. Site counters are not all allocation/copy/hash work, and external proof artifacts have not been kernel-rechecked. Subsequent stories assess feasibility without shipping an optimization or treating these limits as new Core semantics.
