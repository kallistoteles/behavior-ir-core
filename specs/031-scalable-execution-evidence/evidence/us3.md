# US3 — Broader incremental queries

Disposition: **supported-by-evidence** for the conditional finite-map value argument; **unresolved** for a complete Core optimization. No Core query language or supported program is changed.

The [correspondence argument](algorithms/correspondence.md) proves the count identity by partitioning arbitrary finite maps into changed and unchanged identities, under total fixed predicates and complete identity-bearing before/after deltas. Existence follows for that total fragment. Typed-key frequency maps and nonnegative, representable sums have conditional arguments; arbitrary signed checked sums and partial/lazy queries require more than a group-value equation.

Eight independent native Core oracle tests produced 32 frozen complete read/decision/refusal observations before the helper existed: empty/nonempty count/existence/unique/sum, membership entry/exit/reactivation, creation/removal/reused identity, unchanged aggregate with changed complete record, captures, Option/None, checked overflow and lazy/partial query order. [Reference manifest](algorithms/query-reference-manifest.json) binds exact source and bytes. Two failed setup attempts assumed the wrong legacy error envelope; they remain in `core-oracle-001/002.txt`. The corrected oracle follows wire 0.7: partial query evaluation reports UNKNOWN_FACT with division-by-zero message, while sum overflow reports EVALUATION_ERROR with numeric-overflow message. These are preserved observations, not normalized into a boolean or a new Core error.

The test-only helper then checks complete before values, unique identities, complete resulting map, fixed capture and retired identities. It passes all 729 pairs over three identities, each absent or holding x=0/x=1 and explicit adversarial cases. Ten focused tests pass; the diagnostic group has eleven, including the retention counter control. The initial unchecked helper fails actual assertions. Five isolated standalone Rust mutations each compile, then return a count for invalid input and fail the independent assertion; the corresponding checked programs all pass. [Mutation results](algorithms/premise-mutation-results.json) preserve source hashes and observed wrong returns. No compile/tool failure is counted as a premise counterexample.

This is a one-entity-type finite-map experiment, not an action/effect extractor or Safety certificate. The complete supplied resulting map is independently checked, so construction/counting, cloning and equality are O(N), with O(D log N) map updates. The arithmetic delta portion is O(D); the complete checker is not. Initial/rebuild storage is O(N), and current Core observation emission remains O(B). No experiment timing or end-to-end speedup is claimed.

A Core implementation still needs mechanically complete typed action/delta and dependency extraction, actual capture binding, checked Int representability, ordered errors/traces, exact module/profile/policy/history identity, safe fallback and full-workflow comparison. A producer supplying identical claimed captures does not establish that the real Core inputs were unchanged. Omitting a dependency is modeled by a missing delta/capture control; no graph extractor was implemented or verified. A parent/capture update may legitimately affect many unchanged children, so no universal cost proportional only to directly written rows follows.

DBSP, Differential Dataflow and Adapton are assessed in [sources](algorithms/sources.json) and [proof scope](algorithms/proof-scope.md). External artifacts were source-inspected, not independently kernel-rechecked. No new Lean/runtime dependency was added. Existing Core `incremental_proof` files are test-only replacement/composition/operator controls, not a machine-checked proof of a new query engine. The promising next implementation fragment is total local filtered count with explicit captures and complete typed deltas, while preserving full reference behavior and current output. Its complete Core correspondence and practical benefit remain open.
