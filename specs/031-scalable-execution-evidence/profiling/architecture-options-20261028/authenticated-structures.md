# Authenticated structures beyond a Git-style object DAG

Research date: 2026-10-28. Exploratory source review for branch `031-scalable-execution-evidence`, HEAD `a8215c1`. No implementation or dependencies were changed. Proof artifacts and benchmarks were **not installed, built, or independently reproduced**; machine-checking claims below are the authors' reports, with public artifacts identified where found.

The [local profile](../single-create-20261028/report.md) measures a 4,085,191-byte record at 8,192 parent entities: 79% repeated constraint traces, 10% field facts, 8% parent universe, 3% query members; median evaluate/commit are 277/1,658 ms. Repeated parsing, typed validation, cloning, serialization and hashing remain substantial despite reuse of old predicate results. The options address different layers and can be combined. None establishes end-to-end correctness of Behavior Core.

## 1. Authenticated computation with proof reuse and validated value caching

**Primary sources and evidence.** [LambdaAuth, POPL 2014](https://www.cs.umd.edu/~jkatz/papers/ADS.pdf) derives prover/verifier programs from authenticated types; its theorem covers a formal core calculus under collision resistance. The newer [Authentikit proof, CCS 2025](https://iris-project.org/pdfs/2025-ccs-veriauth.pdf), §§4–7, reports Rocq/Coq + Iris mechanization of security/correctness, proof-reuse buffering, caching deserialized authenticated values, stateful caches and an optimized Merkle retrieval. Security relates accepted verification to ideal execution on collision-free traces; correctness relates honest prover, verifier and ideal results. These are theorems about translated programs in `Fω,μ-ref`, not a verified OCaml compiler: faithful translation to compiled OCaml semantics is explicitly trusted (§2.2). The performance study substitutes OCaml Marshal/file streams for the Rocq-verified serializer (§8); its measured binary must not be described as wholly verified.

**Public artifact.** [veri-auth](https://github.com/jtassarotti/veri-auth) separates `theories/`, OCaml `src/basic/` matching the development, and optimized `src/opt/`. The README lists proof-buffer/cache correctness and security files plus serializer implementations. Source layout/build instructions were inspected; no axiom audit or proof build was performed.

**Related formal models.** Isabelle AFP's [LambdaAuth entry](https://isa-afp.org/entries/LambdaAuth.html) (2019) reports correctness/security proofs for the calculus and repairs to the original informal proofs. [ADS_Functor](https://isa-afp.org/entries/ADS_Functor.html) (2020) supplies modular Merkle datatypes, inclusion proofs and a Canton transaction-tree model; the entry presents this as a first step toward protocol integrity/security verification. The latter is useful composition vocabulary, not evidence that arbitrary Core queries or the Canton protocol are verified. Neither AFP development was built here.

**Core inference / minimal experiment.** This is the closest match to the measured duplication: intern immutable evidence nodes; strictly decode and validate a node before placing its typed value in a verifier-owned cache. Compare cold and warm replay of a small batch with repeated field/trace dependencies; instrument unique decodes, validations, bytes, and exact reconstructed trace/error order. Cache identity must include object kind, schema/semantic version and applicable module context. A valid content hash authenticates bytes, not their rule validity. This pattern alone does not justify skipping unchanged constraints or proving a query complete.

## 2. Partially verified Merkle-Patricia map: Plebeia

**Primary source and proof scope.** [Sato et al., 2021](https://arxiv.org/pdf/2106.04826), §§5.1–5.6, reports F* verification of core tree/cursor invariant preservation, nested-map functional behavior, storage serialization/deserialization, and a relative hash-collision reduction. OCaml extracted from the verified modules is linked with unverified library code; declarations for untranslated functions are assumptions. Disk-function termination is assumed for well-formed disks (§5.4). The reduction assumes security of the first 222 BLAKE2b bits, including difficulty finding a zero-digest preimage (§5.5); it does not prove the cryptographic primitive secure. Reported extraction/tests do not verify the extraction/compiler/runtime chain. The paper links its [F* branch](https://gitlab.com/dailambda/plebeia/-/tree/banno%40port_into_fstar/fstar); that page returned only a loading shell in this review, so artifact contents/build were not checked. Evidence is an author-reported partially verified implementation, not merely an abstract map theorem, and not whole-library verification.

**Core inference / minimal experiment.** Use the model for an immutable entity/field map with explicit get/insert/delete laws and canonical encoding round trips. Exercise absent keys, deletion, shared paths, corrupt encodings and missing nodes against full-map replay. A point lookup/nonmembership path does not establish complete arbitrary queries, Ref integrity or global predicates. Core would still need a verified relationship between the auxiliary map and authoritative state, preserving MuHash3072 and exact HistoryRef semantics unless explicitly versioned.

## 3. Ordered authenticated indexes with complete range proofs

**Primary source and evidence.** [Li, Hadjieleftheriou, Kollios and Reyzin, SIGMOD 2006](https://users.cs.utah.edu/~lifeifei/papers/sigmod06-btree.pdf), §3.3, describes the Merkle B-tree: a range response includes returned records, neighboring boundary records, sibling digests and enough grouping information to reconstruct its authenticated root. This makes omitted interior records detectable and checks range endpoints. The paper distinguishes correctness, completeness and freshness. Evidence: published algorithm/security reasoning, analytical cost model and author-run prototype experiments; no machine-checked implementation claim was found.

**Core inference / minimal experiment.** Authenticate a canonical ordered entity-type index or a `(type, field-value, entity-id)` index. Verify range coverage, empty results, ties, domain endpoints, deletion and insertions into formerly empty gaps; compare every answer with full-universe evaluation. Bind the root to the exact parent HistoryRef. Revalidate index maintenance against authoritative entity changes. A producer-signed or hashed index is insufficient if the producer may omit source rows. A count/min/max summary additionally needs a checked leaf-to-summary maintenance law; its hash alone proves no aggregate invariant. Predicates outside the indexed order may still require scanning every matching candidate, and full query output remains proportional to result size.

## 4. Prolly trees: canonical chunking and structural sharing

**Primary sources and evidence.** Dolt's [chunking description](https://www.dolthub.com/blog/2022-06-27-prolly-chunker/) describes sorted keys, content-defined boundaries, content-addressed nodes, history-independent shape, and local boundaries intended to avoid insertion-induced rewriting of the whole suffix. Its [Prolly tree overview](https://www.dolthub.com/blog/2024-03-03-prolly-trees/) describes shared chunks and subtree-skipping diffs. Evidence: implementation-publisher architectural/performance claims, not a formal theorem or independent benchmark in this review. No proof of a complete hostile-server query protocol was established from those sources.

**Core inference / minimal experiment.** Chunk canonical entity maps or large ordered trace collections; update one entity and measure newly stored bytes and nodes read. Rebuild the same map after shuffled insertion/deletion histories, checking identical roots and canonical expansion. Fix ordering, chunker parameters, encoding, hash domains and versions. History independence is useful for state equality and rebuilds but deliberately erases update history: retain HistoryRef separately. Chunk sharing reduces repeated storage/network transfer; it does not remove per-entity logical evidence obligations. A new compressed record format must specify exact expansion to canonical traces/errors/order, or explicitly change that contract.

## 5. Verified crash-safe storage refinement: VeriBetrKV

**Primary source and evidence.** [Hance et al., OSDI 2020](https://www.usenix.org/system/files/osdi20-hance.pdf), §§2–3 and 6, reports a Dafny-verified copy-on-write Bεtree with a journal, cache and refinement to a crash-safe dictionary specification. Its persistent/frozen/ephemeral trees separate acknowledged durability from ongoing writes. The proof trusts specifications, OS/runtime interfaces, verifier/compiler/toolchain and a disk corruption model that excludes corrupted blocks with valid checksums. The paper explicitly says an adversarial disk or stale-block return can violate that model. Evidence: author-reported verified storage implementation with stated assumptions; **not** cryptographic authentication against an untrusted storage server. Builds were not reproduced.

**Core inference / minimal experiment.** Borrow the refinement boundary and publication protocol for an evidence object store: write/validate child objects, make them durable, then publish the exact-history root atomically. Fault-inject interrupted object writes, root publication and recovery; require either the previous complete history or the next complete history. This targets reliable persistence and cache lifecycle, not the 79% trace component or Core's independent replay theorem.

## Cross-cutting acceptance conditions for Core experiments

The following are proposed Core requirements, not established properties of the external projects:

- Keep state commitment, exact history commitment, evidence identity and semantic validity distinct. Equal MuHash/state or Prolly roots do not imply equal histories, complete queries or valid rules. Anchor auxiliary roots to a checked exact-parent transition; do not promote producer-provided metadata into authority.
- Model positive reads, negative reads, complete ranges, query membership and Ref targets as dependencies. A create can invalidate a previously empty query or absence fact even when no previously read entity changed. Unchanged field hashes alone do not discharge global constraints.
- A proof-aware replay must reconstruct the same normative successful traces, errors and ordering, or introduce a deliberately versioned contract with a proven correspondence. If the external consumer still requests the entire old JSON record, emitting that record remains linear in its size.
- Start fresh with empty caches and only the published export. Every required referenced object must be included or retrievable; recursively verify reachability, encoding and hashes before use. Missing/corrupt objects must reject, fetch or trigger a validated rebuild, never silently count as an empty result or a satisfied obligation.
- Rebuild auxiliary indexes, summaries and caches from retained authoritative history/state and verify their roots. Retain all evidence objects required by published histories; specify pruning/export/garbage-collection reachability. A compact root supplies neither object availability nor a cold-start reconstruction procedure.
- Report record bytes versus distinct stored bytes versus transferred proof bytes separately, along with cold/warm replay CPU, parsing counts, peak memory and incremental update cost. Repeat the measured workload with independent full replay and adversarial omission/stale-history cases before making speedup claims.

The lowest-risk first comparison is an in-memory verifier-owned cache of already strictly validated immutable nodes. The next architectural comparison is ordered complete-query evidence, followed by shared canonical evidence chunks. None requires replacing MuHash3072 merely to investigate the design.
