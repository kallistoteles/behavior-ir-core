# Correctness contract

This is a proof/build target, not an existing proof. Core's admitted semantics remains normative. A checked fragment theorem and differential native agreement are distinct evidence classes.

## Declared fragment and fallback

The fast selector requires exact admitted LD8 bytes/schema/profile/policy set, the current expected history and writer boundary, established valid typed parent facts, action finish, one existing Child binding, no changed ownership and no create/remove/command effect. The action sets that child's phase to Terminal. Arbitrary finite live maps are permitted; there is no N/H bound in the mathematical domain. Gone and Abandoned remain distinct exact-result values. Already Terminal children are included and must preserve original unchanged-content/history behavior. Native correspondence requires ordinary checked representability of typed values, counts and history position/successor; mathematical unbounded coordinates do not authorize native overflow. Outside those premises retain original errors or reference fallback, without capping the proof domain at benchmark N/H.

Do not require the rest of the LD8 action inventory to be removed. Activate and all other actions execute ordinary Core. Missing bindings and malformed/unsupported requests follow the original resolver/error path. Unsupported expressions, captures, policies, schemas, changed owners, lifecycle changes, read modes and command variants select the reference path. Selection cannot introduce an earlier semantic refusal or skip an existing mandatory phase.

A maintained owner/active-child index may support frame/coverage diagnostics and future work, but this study does not add a fast stop action. Tests that change membership must invalidate any stale result/view; ordinary fallback remains the authority for those actions.

## Two independent mathematical obligations

Define a finite typed state with parent/child maps, full phases, ownership, live and ever-used identities, ordered command history and logical history coordinates. Define reference execution and incremental execution independently:

- Reference computes the ordinary logical resolution/action/validation result and full ordered observation from canonical state.
- Incremental resolves the same bound child, applies a point update, evaluates affected obligations and reuses only components whose full inputs/observer effects are proved stable.
- A view relation is equality to reconstruction from canonical state, not an imported validity flag.
- An observation is a concrete ordered record tree, including subject/phase/location coordinates, input and effect facts, errors/skips and command multiplicity. It is not an uninterpreted proposition asserting two outputs are equal. Freeze a complete normative field/phase inventory traced to pinned `crates/behavior-core/src/invocation.rs`, `record.rs`, `eval.rs`, and `crates/behavior-store/src/documents.rs`/`store.rs`. Omitting the same original field from both model algorithms does not satisfy whole-observation equality; missing-field and stale-coordinate mutations must fail independently of final state equality.

Prove exact observation equality separately from preservation of the original invariant/property set. A state that remains safe but ignores finish is a mandatory counterexample to conflating the two.

## Original observation and identity floor

Use the same existing invocation envelope, inner decision/evidence, bundle, commit record and canonical hash encoders as reference Core. Compare their entire normative content and identities, plus actual stored arguments/records and original Safety outcomes. Separately authored facts prevent a shared implementation error from becoming an unquestioned oracle. A preservation-derived Safety ground uses distinct core035 provenance, not an original direct-check StateValidationRecord. Required original direct-validation records must be produced by the actual original check and charged inside the complete endpoint; independent oracle results cannot be presented as that candidate check having run.

All bytes needed for an original required record/hash remain mandatory before the corresponding commit/completion boundary. An audit recipe can delay only optional reconstruction; it cannot move required hash/evidence work out of the complete endpoint. Reconstructing a full population-shaped original record can legitimately be O(N); report it. Do not claim complete local latency from the local semantic-work theorem.

## Negative and operational controls

At minimum test: safe-but-wrong finish; missing original observation fields and stale coordinates despite equal values; missing/omitted dependency; empty-set/new-member and changed-capture/owner behavior; corrupted view; wrong branch/position with same content; invalid starting state; forbidden parent/Safety violation; duplicate ordered LD8C commands; first reachable error, short-circuit and overflow fallback; stale/failed/uncertain commit; restart/untrusted authority; unknown/global fallback. Kernel-check genuine countermodels for unsafe implication claims where modeled; retain actual native reference confirmations separately.

Actually performed backend calls retain their errors. Hypothetical failures of omitted redundant calls, traces, diagnostics and timing are not canonical semantic observations. Every omitted mandatory semantic/integrity/snapshot/identity/trust/concurrency obligation still needs equivalent evidence.
