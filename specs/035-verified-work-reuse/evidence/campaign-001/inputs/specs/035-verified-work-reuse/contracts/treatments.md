# Treatment and conformance contract

## Common authority and reference

Each group actually checks its exact program context before first authority use; every sample independently acquires the expected prefix and valid parent under the same original Core/Safety/host premises. All treatments use the same `Store<Capture>` and memory backend contract. The parent/request/expected original outputs are identical within a cell. Canonical acquisition is independent of candidate-maintained views; a producer flag cannot create authority.

The unpatched upstream oracle runs pinned public Core/Safety. The research reference strategy must match that oracle for full native outputs, stored records/arguments, identities and original properties before comparisons are accepted. A source hash or passing local model is not a substitute for this check.

## Factors

| Worker | G: retain authorization for exact checked facts | V: derived execution/property/version views | Required behavior |
| --- | --- | --- | --- |
| R | No additional reuse across selected boundary | Ordinary reference work | Discard selected reusable authorization; establish necessary facts normally; use ordinary invocation and full original property/materialization path. |
| G | Yes | Ordinary reference work | Retain exact ground, otherwise the same reference invocation/property/observation work. |
| V | No additional reuse across selected boundary | Yes | Retain data only as untrusted acceleration material; re-establish required validity/coverage and charge it before use. Apply the justified view path only afterward. |
| GV | Yes | Yes | Retain exact ground and derived views; use justified point updates and original envelope/identity/commit path. |

Use a narrowly scoped research reset/retention adapter to avoid changing backend type, actual canonical state or both factors accidentally. Reconstructible view data may remain resident in V, but its checked binding/authority must be absent until re-established. The already acquired expected-prefix provenance is common starting knowledge for all four. G varies the permission to reuse the selected engine-owned snapshot/validation facts across the operation boundary, not whether the common prior acquisition happened. All auxiliary seed construction, validation, refresh and retained space are charged. V may remain O(N); this interaction is a valid outcome. If the source design cannot independently vary the two factors, mark the affected causal comparison `confounded` and do not claim factor attribution.

G1 retains facts established by actual checks, never imports checked JSON. Binding includes exact history, full relevant admitted content/schema/profile/policies and uninterrupted writer boundary. Unsupported transitions invalidate/rebuild as required rather than carrying an unproved ground. Failed/uncertain transitions never authorize a child.

## Executed identity and mechanism gates

Use four unique bin targets in package `reuse-study035`, with explicit mechanism-specific entry points. Freeze each target, source/patch context, actual Cargo dependency graph/build command/toolchain, executable size/SHA and embedded treatment. Run fixed retained binaries, never a later mutable target path. Same-name sibling manifest copies are forbidden. Four equal binaries cannot implement this comparison.

Required activation tests must also distinguish meaningful behavior:

- G0 forces the selected re-establishment on the same parent; G1 avoids that redundant pass while retaining exact bindings.
- V0 follows the ordinary materialization/evaluation route; V1 runs the selected prepared/view path, applies the staged update and handles invalidation correctly.
- A distinct worker whose entry accidentally calls R fails activation even with a different label/hash.
- Missing/corrupt/incompatible view data cannot yield unchecked acceptance.
- Replacing a worker or flipping its declared G/V identity fails before semantic preparation/growth.

Detailed work counters and marker fields are diagnostics, not evidence of semantic correctness by themselves. Mutation controls must fail for the intended reason. Unavailable tools or non-collected tests are not successful controls.

## Original observation contract

Use the original resolver, scalar evaluator where applicable, shared invocation envelope, exact bundle, ordinary commit rederivation and canonical encoders. Do not handcraft substitute invocation JSON or benchmark a deprecated evaluate call as if it were unified invocation.

Compare complete original decisions, values, evidence/trace/read coordinates, errors/refusals and validation order, skipped entries, command multiplicity/order, stored transition arguments, state/history identities and original Safety outcomes. Exclude only declared diagnostic timing/counters/paths and backend traces. Required original observation must be persisted before the native complete endpoint. Required hash production cannot be deferred to optional audit.

The full original Safety check runs independently outside candidate timing as a conformance oracle. Preservation-derived grounds carry distinct `core035` research provenance; they MUST NOT synthesize an original StateValidationRecord claiming direct CoreStoreExport/executable validation occurred. Original Safety records come only from actual original checks. Compare property outcomes independently; if an original direct-check report is mandatory for a compared endpoint, perform that original check and include its production cost inside the complete endpoint as well. Freeze that requirement from the actual caller contract before execution; it cannot be waived after observing cost. Within the candidate operation, it is either actually performed or discharged by the checked restricted preservation argument plus its explicit native premises. If that argument is unavailable, perform the full check and report its cost; do not omit the obligation while calling the candidate equivalent.
