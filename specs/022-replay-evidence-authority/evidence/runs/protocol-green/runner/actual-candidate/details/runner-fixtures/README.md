# Core 022 replay fixtures

These files retain original records produced through existing public Core and
Store operations on implementation base
`f0d2a5102adcb0b491cac166f023fd87bb03e7a7`, whose runtime includes frozen 018
`391017e536ff64ddf94999ec126bc71799952264` and 017. They are new captures, not
exploratory investigation receipts or rewritten historical 018 archives.

The capture implementation is the test-only
`crates/behavior-store/tests/replay_evidence_authority.rs` target. The coordinator
retains the actual command, source/test digests, environment and logs in the
feature's execution ledger and source-custody manifest. A named source revision
alone does not establish that a capture or regression was executed.

## Original operations and setup

`stores/culture.json` references the unchanged 018 M08-C-D Wire 0.8 module. The
capture creates an actual Store with `Culture#c1.measurements = 7` and evidence
policy `none`. Its data version comes from that Store's public identity/current
state APIs. `stores/snapshot.json` contains the actual loaded entity value and a
coherent complete Culture universe at exactly that coordinate. No standalone
record is assigned an invented Store coordinate.

Each `stores/attempts/<case-id>.json` retains the original operation arguments:

- `store_read` retains read name, targets, input and context, including arrays.
- `invoke_document` retains document, supplied Snapshot and the host-context
  discriminator. Null means the host-invocation route; an object selects intent.
- `store_intent` retains the intent document and host context.
- `store_invocation` retains the typed requested invocation document.

`records/<case-id>.json` contains the original API record JSON plus a final newline.
Its identity, original refused text and document archive are retained unchanged.
Normal tests reproduce these same operations and compare exact original file
bytes. The explicit capture mode refuses to overwrite any differing existing file.

The four R022 cases are genuine Store input/context-array reads and host
invocation input/binding-shape refusals with a coherent actual Store Snapshot.
Seven ordinary read, semantic input, binding, successful host invocation, intent
and wrong-type controls establish that setup is legal before asserting corrections.

Rejected-Snapshot cases use both host and intent document routes. Malformed
`entities` and contradictory entity/existence facts make `Snapshot::decode` return
None. Their rejected contents are attempted-input evidence; matching replay does
not establish those contents as historical truth.

Sparse controls deliberately establish accepted Snapshots. Positive existence
without a value or complete universe reproduces `INCOMPLETE_SNAPSHOT`; Store must
check the explicit existence claim without filling the missing original value.
False positive existence, false negative existence and an empty Culture universe
are separate historical-truth negatives. A binding refusal may archive no Snapshot;
its performed unknown binding still asserts absence. Missing capture must never
be expanded into an invented full-Snapshot equality obligation. The false-negative
and empty-universe attempts can yield the same canonical record identity because
those distinct original Snapshots are not retained by that record path.

## Inventory and evidence limits

`matrix.json` is a reviewed required inventory, not executed coverage. Its
`runner_case_ids` select the actual replay corpus. The inherited 018 cells,
unsupported/admission cases, protocol checks and explained N/A routes are separate;
they must not appear as canned replay-runner output. Pending cases have no fabricated
fixture, coordinate, identity or successful execution status.

Inherited records remain under `tests/fixtures/replay/018`; this feature references
their original matrix and fixtures instead of copying or retagging them. No v1
archive is generated by changing the format of a current v2 record.

`checksums.json` hashes exact captured record/setup/attempt bytes and this README,
and separately identifies the unchanged external module input. The evolving
inventory and checksum file itself are excluded from archive byte custody. The
feature's root-owned source-custody artifact and retained run receipts bind the
capture and subsequent named RED/GREEN evidence. Corrected Store expectations
never change the original records or imply that baseline Store replay matched.

## Explicit capture command

From the Core root, after the coordinator has established evidence conventions:

```bash
nix develop -c env CAPTURE_REPLAY022_FIXTURES=1 cargo test -p behavior-store --test replay_evidence_authority baseline_capture_is_genuine_and_reproducible -- --exact --nocapture
```

Without that environment variable, the test verifies custody and performs no
fixture writes. Fixture capture is test/setup evidence; the four exact named Store
regression commands separately establish semantic RED and later GREEN.
