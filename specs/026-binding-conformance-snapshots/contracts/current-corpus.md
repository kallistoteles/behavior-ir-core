### Why these empty memberships are deliberate

- Invoice is an invoice-only persisted world. Actor anna is a context User with the original role/limit, not asserted persisted membership. Invoice.approved_by is an optional plain Id<User>, not a Ref; User=[] is a documented scenario choice, not inferred absence.
- Accounts allowed has no accounts and neither case has audit notes. The observations respectively assert incoming(c2)=[] and incoming(c1)=[Account#a1.owner]; W06 contains that actual typed source row and target.
- Orders cases have no employees. The employee-personnel uniqueness invariant holds on the deliberately empty type. W09 includes unrelated c2 and its open order as explicit scenario content; Order.customer is a plain Id, so its survival after c1 removal is not reinterpreted as dangling Ref failure.
- Project and ledger have only the one declared type shown.

Parent validity requires nonnegative Invoice/Account/Order monetary values, actual targets for Account.owner Ref, applicable entity rules and the employee uniqueness global. Project revenue zero is a valid parent: the action guard prevents reaching division. Never alter that guard to accommodate an example.

## Current generator interface

`python3 tests/fixtures/bindings/generate_current.py [--output-dir DIRECTORY | --check]`

- Default writes exactly the ten current request paths. `--output-dir` writes only those ten flat filenames into a separate request directory. Reject an output destination that could overwrite protected historical files.
- `--check` generates in memory/temporary output and compares with checked-in current requests, without rewriting them.
- Consume cases/worlds and unchanged historical module/request intent. Fail for unknown/missing case/type, duplicate identity, mismatched binding/observation or unreviewed input drift. Never use `setdefault(type, [])` to fill an absent authored universe.
- Only requests are output. Full expectations, worlds, identities, historical files and metadata are independently reviewed inputs and are not rewritten.
- Use compact sorted-key UTF-8 JSON, deterministic type/identity ordering and no floats; preserve Core value meanings. The generator is not a type checker or evaluator; executable Core checks remain necessary.
- Two separate temporary regenerations must equal each other and the delivered request files. Fingerprint protected files before/after and check original archive digests subject only to the already established 017 documentation exception; grant no 026 exception.

## Public consumption

The current README and root README identify `current/cases.json` and the current requests as the fresh-evaluation entry point. Old pairs remain clearly historical and retain replay meaning. The packaged runner can be invoked after extraction with an explicit package root and a matching Core CLI. A binding can also directly evaluate the same request files: no private completion helper or Python authoring DSL is required.

The corpus reference revision is immutable semantic provenance. Actual candidate execution and future releases bind their exact commit/binary/engine-info/archive through execution receipts and the existing release-manifest; the caller's request git_revision is not used for that purpose.
