# Core036 full reproduction and final closure

Full reproduction is a required implementation phase. This planning document supplies a protocol, not a completed reproduction. The old limited archive validation remains historical evidence under specification revision1.

## Independently selected context

The verifier's `ExpectedContext` is outside candidate output. It fixes spec-v2, original semantic authority, exact source/configuration/model/proof roots, full closure/tool identities, canonical/compact contracts, all control IDs, slot matrix, numerical decision rules and v1 archived-path mapping. Verify all byte refs, bounds and source/gate dependency relationships before executing. Reject candidate-supplied verifier paths, success flags, stale roots or changed expected types.

Use separate fresh owned build/proof targets with the same pinned native configuration. Existing source/dependency caches may be explicitly warm, but do not reuse emitted candidate binaries as fresh builds or compiled proof objects as fresh kernel checks. Record actual tool closure and new resources inside a declared REPRO attempt. If stopped, preserve partial scope and declare a corrected successor; missing full reproduction keeps the feature unfinished.

Cross-boot cumulative durations must not mix monotonic origins.

3. Rebuild unpatched oracle and R/GV/B/C from the selected final subject(s). Check actual compiled Core identities, source/cfg and role activation. Run the entire unchanged canonical gate with actual CLI and all scoped research/determinism checks for the relevant final subject.

5. Execute the fresh semantic verification matrix below, using original oracle execution on the same inputs and full original bytes/values/identities at declared endpoints. These are one verification observation per cell, not replacement timing triplets.

Recompute every table from all primary raw observations: complete intervals/exclusive remainders, quantities/units, medians/ranges, session totals, payback, compact comparator selection, retention/audit costs, thresholds and recommendation. Derive every FR/SC/deliverable status; reject missing required cells or gap-only passes.

Normative observations/identity/determinism must agree exactly. A discrepancy is repaired through a new source/attempt and affected gates/measurements are rerun; no unexplained reproduction gap remains in final completion.

## Completion evaluator

Use a typed predicate over actual records, not hardcoded native-false/native-true output. All eight mandatory deliverables, FR-001–FR-022 and SC-001–SC-008 must be satisfied; every required comparison/control/reproduction slot exists; current proof/quality/source/endpoint gates match; and product adoption remains unactivated. Unknown, blocked, not-run, unsupported or unestablished never coerces to met. All documented external premises have their declared legitimate scope; no desired-equivalence assumption is concealed.

A completely checked candidate may have poor cost or no payback and receive `not_recommended_for_declared_endpoint`. That can be a completed scientific outcome. Missing implementation/proof/quality/reproduction is an unfinished feature, not a negative architecture decision. Ratios/ranges and actual endpoint guarantees determine the cost conclusion under the predeclared rules.

## Acyclic closure sequence

1. Finish all attempt children/writers and retain actual binaries, generated proof inputs, complete outputs and logs. Seal each attempt create-once.
2. Create a frozen candidate assessment referring only to closed existing subjects/results; it is not final feature completion.
3. Run independent reproduction in separate owned roots under independently selected context. Close its supervisors and writers, then seal reproduction. A supervisor receipt written after an inner seal belongs to its separate launch root.
4. Recompute the final completion predicate from candidate and independent results. Emit final report/assessment/completion under `results/v2/<work-id>/`, binding both earlier seals and exact final verdict. Seal result files in a separate index that is not part of its own file list.
5. Recheck selected preservation and all closed references in a new external final-review record. Never append a correction to an already sealed archive or make any record bind its own future hash. A later correction is a named successor record/attempt.

Independent validation may produce a useful unfinished checkpoint with actual completed scope, but `finalize` returns3 until the full predicate passes. No future/invented digest, unlimited retry or project-lifetime timeout is used to manufacture completion.
