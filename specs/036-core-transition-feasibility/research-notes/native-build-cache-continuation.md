## Decision

After the proposed shared I/O/hash changes, use a **new source-bound native build**, retaining the offline Cargo source cache. There is currently **no demonstrated surviving native compiled dependency target** to reuse. Admission of a complete replacement build within the existing caps is **not yet proven**. First close327, then obtain one bounded metadata inventory of explicitly selected closed disposable candidates and their retained-output costs; reclaim only after exact executable retention and the existing ownership/lease checks. If measured reclaim cannot fund build, outputs, and closure reserve, stop before building rather than silently enlarging limits.

The existing native completion helper is for unchanged301 Rust only. Reusing its old77 tests or12 conformance observations after changing shared source would break the compiled-source binding ([completion source:75](../../../experiments/transition-study036/native_completion_v2.py#L75), [source verification:112](../../../experiments/transition-study036/native_completion_v2.py#L112)).

## What the actual reuse paths do

`native_build.py` always copies `src`, `tests`, `expected`, and oracle input sources into a fresh `native-builds/<new-attempt>/worker`, and writes a new manifest and frozen identity. It normally chooses `disposable/native-<new-attempt>/target`. Development/full-native slots first try the hardcoded `native-a0007/target` **only if it exists**. A predecessor route can use the target named by `native-builds/<predecessor>/result.json`, after closed-checkpoint verification and retention, when that target still exists. `native-development-reuse.json` separately causes retention of its selected old build; it does not itself select its target. None of these paths reads `native-completion/a0303/result.json` as the predecessor build result ([copy:330](../../../experiments/transition-study036/native_build.py#L330), [target selection:415](../../../experiments/transition-study036/native_build.py#L415), [retention binding:305](../../../experiments/transition-study036/native_build.py#L305), [current reuse binding](../../../experiments/transition-study036/build-inputs/v2/native-development-reuse.json)).

The shared `P/cargo/registry` and `P/cargo/git` directories exist. The native executor uses that same `CARGO_HOME`, locked/offline Cargo, fixed Rust1.98.1, one job, no incremental state and fixed linker/CPU flags. Thus downloaded/resolved dependency **sources** can be reused without a download; completeness is checked by actual offline metadata/build, not by directory existence ([native environment:459](../../../experiments/transition-study036/native_build.py#L459), [metadata:505](../../../experiments/transition-study036/native_build.py#L505)). Keeping this home is materially different from claiming reuse of compiled dependencies.

`analysis-a0114` and `analysis-a0135` are not demonstrated compatible native1.98 compiled caches. Their small `.rustc_info.json` metadata identifies Rust1.100.0-nightly, whereas301's compiler receipt identifies1.98.1. Extraction additionally uses an explicit target, host linker configuration, and `-C linker-features=-lld`; these differ from the native executor. Pointing native Cargo there would contaminate the useful analysis cache and may simply compile a second artifact family ([native compiler](/var/tmp/behavior-ir-core036-v2/w001/native-builds/a0301/compiler-identity/stdout.txt), [analysis114 compiler metadata](/var/tmp/behavior-ir-core036-v2/w001/disposable/analysis-a0114/target/.rustc_info.json), [analysis135 compiler metadata](/var/tmp/behavior-ir-core036-v2/w001/disposable/analysis-a0135/target/.rustc_info.json), [extraction environment/reuse:288](../../../experiments/transition-study036/extract.py#L288)). Do not use or delete SDK/tool targets to manufacture native cache space.
