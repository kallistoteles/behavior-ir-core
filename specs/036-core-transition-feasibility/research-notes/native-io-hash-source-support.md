# Minimal shared I/O and hash source support for T052

Local-source investigation, 2026-11-18. This is a proposal for representable source/model boundaries, not an implementation or native-equivalence result. No tests, builds, downloads, selected-input changes, or generated-body edits were performed. All native B01–B10 obligations remain unestablished. T052 itself requires genuine shared Rust refactors or source-bound frontend/model support and retention of unsupported dependencies ([tasks.md:112](../tasks.md#L112)).

## Findings and proposed minimum

Three small changes address distinct representation problems:

1. Add an actual shared `serialization::write_value<W: std::io::Write>(writer: &mut W, value: &Value) -> serde_json::Result<()>` whose unchanged operation is `serde_json::to_writer(writer, value)`, and use it at all three current `to_writer` call sites in `output.rs` and `io.rs`.
2. Replace only the immediately invoked buffered-output closure with an ordinary transparent helper accepting `&mut BufWriter<W>`; retain `let result = helper(...); buffered.into_parts(); result?;` in that order.
3. Add two actual concrete hash-to-String wrappers under the already opaque shared `serialization` module: one accepting `&Vec<u8>` and containing `format!("{:x}", Sha256::digest(bytes))`, and one accepting owned `Vec<u8>` and containing the exact existing protocol `new` / domain-prefix `update` / owned-body `update` / `finalize` / lowercase-hex sequence. Replace the three raw-byte callers and the protocol SHA block, respectively.

These are source-support candidates. Moving code into a transparent helper alone does **not** remove its trait dictionaries from generated IR. The serialization wrappers work as representation boundaries only if extraction actually treats their bodies as opaque, as the existing contract selects `crate::serialization` ([contract:38](../inputs/v2/native-codec-contract-002.json#L38), [contract:107](../inputs/v2/native-codec-contract-002.json#L107)). A fresh successor inventory must verify the reached declarations and callers; the old contract does not already inventory these new functions. The body and complete native effects must remain bound for later refinement or justified same-function congruence. Opaque desired Core equality is never an acceptable substitute ([contract:45](../inputs/v2/native-codec-contract-002.json#L45), [contract:120](../inputs/v2/native-codec-contract-002.json#L120)).

## Why the writer boundary targets the actual problem

`Counted<W>` already **owns** `W` (`inner: W`); `deliver` takes `writer: W`, constructs `Counted { inner: writer, ... }`, and buffered mode owns that value inside `BufWriter`. A proposed “make Counted own W” fix changes nothing ([output.rs:27](../../../experiments/transition-study036/src/output.rs#L27), [output.rs:50](../../../experiments/transition-study036/src/output.rs#L50)).

The offending borrowed writer instantiation is at `serde_json::to_writer`: its generic writer argument is passed **by value**, so passing `&mut output`, `&mut buffered`, or `&mut f` selects `Write for &mut W`. The dependency implements `to_writer` by constructing `Serializer::new(writer)` then invoking `value.serialize(&mut ser)` ([serde_json 1.0.151 ser.rs:2177](/var/tmp/behavior-ir-core036-v2/w001/cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/ser.rs:2177)). Actual326 confirms the borrowed dictionary at the real `io.write`, buffered closure, and original delivery calls: [Funs:12938](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:12938), [Funs:17762](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:17762), [Funs:17829](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:17829).

Actual326 also shows why this is more than a naming issue: the borrowed-Write external methods return the writer **and** a backward function, e.g. `W -> ... Result (... × W × (W -> W))`, while the generated borrowed `Write` dictionary plugs those methods into the ordinary writer trait ([template:145](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/FunsExternal_Template.lean:145), [Funs:112](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:112)). Merely changing names or owning `Counted` cannot reconcile that shape.

The proposed opaque wrapper exposes the underlying `W: Write` dictionary and a regular mutable argument, rather than constructing `Write<&mut W>` in each transparent caller. Keep the wrapper concrete in the serialized value (`&Value`), so no generic `Serialize` dictionary is added at callers. Returning `serde_json::Result<()>` leaves the existing caller `?` conversion to `StudyError` in place. A crate `Result<()>` wrapper could preserve that conversion by moving it inward, but creates another source-linkage step without helping the writer representation.

Keep newline `write_all`, flushing, counter bookkeeping, synchronization, and opening files outside this codec boundary. Their current direct calls use `Counted`/`BufWriter`/`File` dictionaries, rather than the borrowed writer dictionary ([Funs:17769](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:17769), [Funs:17836](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:17836), [Funs:12944](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:12944)). Do not replace `write_all` with hand-written loops: this would introduce new interrupted-write, write-zero, short-write, and error-order obligations. The reported actual313 `PtrMetadata` interpreter failure is historical evidence against indiscriminately making the original standard-library body transparent, not proof that a new boundary will typecheck.

Moving a writer into `to_writer` instead would require recovering it afterward; using `to_vec` then `write_all` changes allocation and serialization/write interleaving, performed write calls, partial output and error boundaries. Neither is the exact original streaming operation. An adapter/newtype remains possible but adds another Write implementation and forwarding/refinement work; it is larger than the existing opaque-module seam.

## Buffered closure and cleanup

The current closure captures the mutable `BufWriter` and value and is immediately called. Actual326 translates its `call_mut` into a result, closure state, and closure-state backward function, then uses that function before `into_parts` ([output.rs:70](../../../experiments/transition-study036/src/output.rs#L70), [Funs:17752](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:17752), [Funs:17865](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:17865)). An ordinary helper removes this particular closure/FnMut representation without changing the executed body:

```rust
fn write_buffered<W: Write>(buffered: &mut BufWriter<W>, value: &Value) -> Result<()> {
    crate::serialization::write_value(buffered, value)?;
    buffered.write_all(b"\n")?;
    buffered.flush()?;
    Ok(())
}
```

Call it without `?`, then perform `into_parts`, then inspect the stored result, exactly as now. Propagating the helper error before `into_parts` allows BufWriter drop to retry failed output; accepting that rewrite would change observable behavior. Keep the 65,536-byte capacity, the same error conversions, remaining-buffer checks, and final underlying synchronize ([output.rs:69](../../../experiments/transition-study036/src/output.rs#L69)). This helper alone still instantiates borrowed Write if it directly calls `serde_json::to_writer`; it needs the writer boundary above (or a genuine generic mutable-trait frontend fix). It does not remove unrelated FnMut closures elsewhere, such as `ground` predicate closures.

## Hash boundary and exact evaluation/ownership

The three raw hash expressions have the same native shape, `format!("{:x}", Sha256::digest(&bytes))`: [native_artifacts.rs:125](../../../experiments/transition-study036/src/native_artifacts.rs#L125), [group.rs:25](../../../experiments/transition-study036/src/group.rs#L25), [raw_oracle.rs:236](../../../experiments/transition-study036/src/raw_oracle.rs#L236). Using `&Vec<u8>` preserves the exact current `AsRef` input type and borrowing; changing to a slice likely preserves hash bytes but is an additional equivalence/monomorphization change. Do not return `Sha256`, `Digest::Output`, or `GenericArray`: that exposes the associated-type machinery at the new boundary. Return the final `String` and keep the unchanged lowercase-hex formatting inside.

Preserve call position and lazy evaluation. In `InputRoots::read`, hash only after the byte-count comparison passes (`||` short circuit); in `group::referenced`, hash only after the declared byte-count comparison passes. Hoisting a hash before those checks changes work/allocation and failure behavior. Preserve all path checks, `File::open`, `Read::take`, `read_to_end`, and their first errors. `io::read_bytes` separately uses `(limit + 1) as u64`, while native artifact reading uses `reference.bytes + 1`; this proposal changes neither ([io.rs:11](../../../experiments/transition-study036/src/io.rs#L11), [native_artifacts.rs:104](../../../experiments/transition-study036/src/native_artifacts.rs#L104)). The existing `native_io::other` boundary only wraps the exact original error constructor and does not solve writer or digest representation ([native_io.rs:1](../../../experiments/transition-study036/src/native_io.rs#L1)).

Protocol hashing is a separate concrete operation. Keep clone/object validation/key removal/canonicalization/`serde_json::to_vec` transparent and in order. Move only the block after `body` creation into an owned-body helper. Preserve `Sha256::new(); h.update(b"core035.research.v1\0"); h.update(body); format!("{:x}", h.finalize())` exactly ([protocol.rs:370](../../../experiments/transition-study036/src/protocol.rs#L370), [protocol.rs:385](../../../experiments/transition-study036/src/protocol.rs#L385)). Do not reuse the unprefixed wrapper, concatenate prefix+body, borrow the owned body instead, or replace the two updates with a new API. Those alternatives add semantic/effect or ownership changes. The dependency `Digest` trait has associated output types and its blanket methods route through Default/Update/FixedOutput; the source supports keeping the exact existing sequence rather than assuming a simpler equivalent implementation ([digest.rs:15](/var/tmp/behavior-ir-core036-v2/w001/cargo/registry/src/index.crates.io-1949cf8c6b5b557f/digest-0.10.7/src/digest.rs:15), [digest.rs:57](/var/tmp/behavior-ir-core036-v2/w001/cargo/registry/src/index.crates.io-1949cf8c6b5b557f/digest-0.10.7/src/digest.rs:57)).

Actual326 has two transparent `Digest.Blanket.digest` calls, at native artifact read and raw local-ref ([Funs:13694](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:13694), [Funs:20484](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0326/generated/Funs.lean:20484)); each expands large concrete associated-type dictionaries. `group::referenced` and `protocol::semantic_digest` were not found as definitions in that generated Funs. Preserve their real shared source anyway; absence from this root is not evidence that their semantics are discharged. After opaque wrappers, those callers should no longer force these digest instantiations. This is an inference requiring successor LLBC/generated inspection; other reached library users could retain the same dictionaries.
