## Minimal slice metadata support: exact branch and representation

Charon's [projection definition](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/charon/charon-ml/src/generated/Generated_Expressions.ml:165) says metadata is slice length, unit for sized pointees, and a vtable for dynamic traits. This experiment should support **only metadata reads of supported references to slices** and reject the other cases explicitly. Do not turn all metadata into unit, a fresh unconstrained usize, or the length of the allocation behind a subslice. Native [slice len](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/core/src/slice/mod.rs:118) is exactly `ptr::metadata(self)`; the current Lean [Slice.len](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend/a0054/lean/Aeneas/Std/Slice.lean:51) is already a pure `Usize` containing the modeled slice's list length, with `len_val` at57. The [builtin mapping](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/extract/ExtractBuiltinLean.ml:1347) is nonfailing and unlifted. Reuse that meaning, rather than introduce an external I/O axiom.

Recommended bounded patch to a fresh successor of the supplied verified translator292/base `1dc8ad31b1b062a77c50e29144a6c7bba955fa09` plus the existing NonPos/Map repair003 patches:

1. Recognize `Copy (metadata_place, _)` and `Read metadata_place` where `metadata_place.kind = PlaceProjection (p, PtrMetadata)` **before** the ordinary operand preparation/evaluation branches. In actual313 `Write::write_all`, fun_decl317's metadata `Use(Copy(...))` destinations are already usize; do not add general `TPtrMetadata` coercions unless a retained successor actually needs them. Aeneas's ordinary [preparation](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/interp/InterpExpressions.ml:367) otherwise sends the metadata projection through `InterpPaths` before operand evaluation.
2. Implement a dedicated read-only `eval_slice_metadata` helper. Validate `p.ty = TRef (_, TSlice (element_ty, _), ref_kind)` and the result `TScalar (TInteger (Unsigned Usize))`. Prepare/read the reference's synthetic dereference with `greedy_expand = false`, reusing [access_rplace_reorganize_and_read](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/interp/InterpExpressions.ml:65), [shared_loan_value](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/interp/InterpPaths.ml:76) and normal [borrow dereference](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/interp/InterpPaths.ml:213). A concrete `VAdt` slice uses its field count; construct `Unsigned Usize` through [Scalars.mk_integer_value](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/charon/charon-ml/src/Scalars.ml:110), using the context's target pointer-size check. For a symbolic slice, introduce a fresh usize with a distinct semantic aggregate such as `VaSliceLen of tvalue`, modeled after [eval_discriminant](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/interp/InterpExpressions.ml:1380) and [VaDiscriminant](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/symbolic/SymbolicAst.ml:341). Reference erasure and slice element translation already exist in [translate_fwd_ty](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/symbolic/SymbolicToPureTypes.ml:373). ## Why metadata alone does not establish transparent Write

The exact native [write_all body](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/core/src/io/write.rs:214) loops over the remaining slice, returns `WRITE_ALL_EOF` on `Ok(0)`, advances by `n`, retries Interrupted, and returns the first other error. Preserve this unchanged source; do not replace it with a hand-written Rust loop or a `to_vec`/single-write algorithm.

Read-only parsing of the retained [actual313 LLBC](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0313/worker_entrypoints_names.llbc:1), fun_decl317, found both initial `Use(Copy(local.PtrMetadata))` operations **and later** `RawPtr { place: local2.Deref, ... }` plus a shared reborrow from `local16.Deref`, whose type is a raw pointer. These are explicit retained AST nodes, not a prediction based only on Rust syntax. Current [eval_rvalue_not_global](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/interp/InterpExpressions.ml:1476) has no RawPtr branch; [InterpPaths](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/interp/InterpPaths.ml:196) explicitly rejects raw-pointer dereference. Therefore clearing metadata may reveal a raw-pointer/slice-advancement failure. That successor failure must be retained and reported.

A later legitimate alternative is a source-bound Charon/Aeneas normalization that recognizes the exact safe slice-advance operation and uses existing slice-index/subslice primitives, with bounds and borrow proofs. It must originate from retained native LLBC and preserve the precise `buf[n..]` semantics, including invalid-read-contract behavior; a blanket raw-pointer-as-reference rewrite is not justified. No such normalization is established by this note. Declaring an opaque default, importing a new axiom, or silently adding an opacity pattern merely returns to today's blocker.

## Read: required dependency and continuity work

The real [Read::read_to_end](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/io/read.rs:290) calls [default_read_to_end](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/io/read.rs:846). That helper uses `read` in a 32-byte probe, then `read_buf` in the spare-capacity path; it tracks allocation/capacity, initialized bytes and partial bytes before propagating errors. [Take::read/read_buf](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/io/util.rs:235) preserve the limit, skip inner reads at zero, and perform truncation/initialization/accounting. Neither Take method calls `read_to_end` or `take`. The syntactic dictionary cycle is introduced because the generated opaque helper receives the **whole** dictionary, including the field being defined.

An honest successor must retain the actual primitive methods and their dependencies. At minimum inventory/select the helper and its nested probe, `Read::{read,read_buf}`, and the actual Take implementations reached, then inspect the resulting LLBC before promising a small patch. `BorrowedBuf`/`BorrowedCursor`, spare capacity/MaybeUninit, unsafe `set_len`, allocation failures, Interrupted retries and partial-data-plus-error order remain source/model obligations; the exact helper is not a simple read-and-append loop. Read itself now permits default `read`/`read_buf` forwarding, with a requirement to implement at least one ([trait](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/io/read.rs:86)); preserve actual concrete dispatch rather than assume the generic defaults terminate.

For ordinary `impl_def`, add **bounded, source-bound helper unfolding or a proved dictionary-demand projection** so the helper consumes only the retained `read`/`read_buf` fields and the self variable can disappear. The current elaborator only unfolds tagged defaults; simply including/exposing the helper is insufficient. Avoid mislabeling arbitrary helpers as trait defaults globally. A targeted helper-unfolding attribute or frontend dependency projection needs a small native canary and a no-progress/recursive-helper control. If the helper remains opaque, a theorem that it ignores `read_to_end`/`take` must be proved from its real native/source-bound model; its type alone does not supply that theorem.

Alternatively representing a genuinely recursive dictionary by NonPos/fixpoint requires a real continuity proof for the actual helper in its method arguments. It does not follow from an opaque axiom. The current [extract_nonpos_continuity](/var/tmp/behavior-ir-core036-v2/w001/tmp/nonpos-source/a0273/aeneas/src/extract/Extract.ml:3138) deliberately skips opaque bodies. Switching ordinary Read/Write traits to NonPos, increasing tactic fuel, or adding an unchecked continuity premise would move or assume the obligation. Today's Read diagnostic is structural `impl_def` resolution; a continuity failure is a possible subsequent obligation, not an observed current332 error at405.
