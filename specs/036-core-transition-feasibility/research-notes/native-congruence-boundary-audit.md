## Finding

**A smaller modular proof is legitimate; opaque whole-worker congruence is not a shortcut.** The existing contract already permits unchanged actual-function congruence after function identity, complete arguments and performed-effect conditions agree. It does not demand a proof of SHA or every serializer implementation. It does demand actual source proofs for the differing adapters, native projections, prepared behavior, output completion and session composition. A prospective verification-method revision can replace the extraction construction, with justification and fresh bindings; recording that revision alone proves none of B01–B10. [Correctness construction/congruence](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:30), [FR-002/003](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/spec.md:126), [plan](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/plan.md:153).

Two concrete non-cuts explain why the current closure cannot simply become arbitrary shared callbacks:

- **Same `execute_original_with_metadata` name, different complete receiver.** `ground.rs` sets prepared use false for ordinary/fallback execution, true for selected execution, and then calls the shared helper. The receiver includes the prepared cache/epoch/dispatch state. Equality of semantic rows or request JSON alone is insufficient for same-argument congruence. B05 must prove the actual prepared/original relation, including cache validity, operations, errors and effects. [ordinary mode](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/ground.rs:175), [fallback and selected mode](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/ground.rs:324), [helper invoke/commit](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/observation.rs:40).
- **Same generic `write_value` name, different function instance.** Original delivery uses `Counted<W>`; B uses `BufWriter<Counted<W>>`. For actual files these are distinct monomorphizations/dictionaries and different receiver states/call traces. Universally quantifying one arbitrary `write_value` cannot identify them. Equal Value is only one argument. B deliberately changes buffering and underlying call counts. [original/B branches](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/output.rs:50), [generic serializer](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/serialization.rs:65), [role selection](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/run_v2.rs:26).

## Defensible cuts and theorem shapes

The following are prospective obligations, not existing Lean declarations. Let `Exec f a w` denote the source-bound computation, including returned success/error, panic/divergence, mutated receiver, performed trace and final world. A deterministic computation can use equality; a nondeterministic one needs equality of possible behaviors or an explicitly justified coupled simulation. Equal arguments do not force two sequential OS calls to receive the same environmental response.

**Pure shared calls.** The genuine generic lemma is `∀ (f : A → Result B) a b, a = b → f a = f b`, with `f` the same function at both applications. No output property is assumed. Bind `A` to the complete native input representation and bind the actual function identity, version, cfg/features, concrete types, trait implementation and monomorphization. A source-directed extraction/context theorem must show that the real call sites factor through that parameter; a theorem about a fresh parameter does not replace fixed generated global externals. The accepted root must ultimately instantiate that theorem at the real shared function, with no extra global axiom. [contract](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:44), [strict checker](/data/repos/behavior-ir-core-033/experiments/transition-study036/check_proofs.py:84).

Useful existing cuts are `module_wire`, `value_bytes`, `packet_bytes`, `record_bytes`, `packet_value`, `commit_value`, `packet_from_value`, `scope_from_value`, `history_from_value`, `raw_sha256` and `semantic_sha256`, **only at matched instances and full arguments**. For example equal full `CommitCall`, not equal reduced state, justifies equal `commit_value`; equal exact Vec bytes justifies the same `raw_sha256`, whose `&Vec<u8>` instantiation is deliberately retained. Error mapping/wrapping remains part of the application proof. [wrappers](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/serialization.rs:11), [hash instances](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/serialization.rs:69), [CommitCall fields](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/capture.rs:18).

The largest useful existing pure observation cut is `original_observation`: prove equality of invocation JSON, complete optional bundle, commit arguments, before/after history, post-state and property-status string, then apply congruence to that same function. This avoids extracting its `json!` implementation solely for equality. It does not prove those seven arguments are the required eight-field original observation: its construction includes `transition_record = commit_arguments.get("record")`, and all caller arguments still need B07. Timing/counter values are expressly excluded from this cut. [constructor](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/serialization.rs:39), [reference caller](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/reference.rs:89), [candidate caller](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/observation.rs:107).

**Shared parsing/reading.** One may cut at the same `parse_payload_json` on equal complete bytes and limit, retaining its actual float-admitting instantiation; `parse_json` uses a different const parameter. Prove source wrapper/selection identity rather than posit that arbitrary parser results satisfy projection laws. The byte/depth scan, duplicate-key visitor and end check remain necessary if their behavior is itself used to discharge an input-domain premise. A shared `io::read_bytes` cut additionally needs equal relevant filesystem/handle world and limit, preserving open/take/read/error effects; filename equality alone is inadequate. [parser instances](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/protocol.rs:108), [source parse](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/protocol.rs:118), [actual read wrapper](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/io.rs:11).

**Stateful shared calls.** The elementary shape is `f₁ = f₂ ∧ a₁ = a₂ ∧ w₁ = w₂ → Exec f₁ a₁ w₁ = Exec f₂ a₂ w₂`. Here `a` includes mutable receiver, dictionaries, borrowed identity/alias state and all arguments; `w` includes every observed external state. For merely related worlds, require a separately justified `RelW`-preserving primitive/actual-instance simulation and compose it; do not assume the whole transition's equality as that simulation. Equal result values on success are insufficient: retain first error, receiver/world updates before error, panic/divergence and partial effects. Capture proves why: an Applied commit is recorded before LostAcknowledgement returns Err. [performed lost ack](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/capture.rs:204), [ground failure/quarantine](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/ground.rs:222).

**Required relational theorems, not congruence.** For prepared versus ordinary execution the shape is `NativeRel s_ref s_gv ∧ GroundViewsInvariant g s_gv ∧ Admitted request → StepRel (Exec original …) (Exec prepared …)`, where `StepRel` preserves exact observations/errors/refusals/commands, publication effects and next-state/authority relation. Its hypotheses must be independently established source invariants, not `nativeEval = referenceEval`. Likewise `materialize(view) = state_facts(store,module)` and actual projected Safety preservation must be proved before replacing the original validator's status by literal `"Valid"`. The optimized branch makes that replacement at a real source line. [selected apply/materialize](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/ground.rs:358), [literal status](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/ground.rs:380), [canonical source projection](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/reference.rs:38).

For output, prove each actual adapter refines the same declared serializer byte stream plus exactly one newline on **successful** delivery, and that failures retain their performed prefixes/state without success. B's serializer-byte property across different writer dictionaries requires actual serializer/writer naturality or an equivalent source proof; an arbitrary shared serializer callback can write unrelated bytes at each dictionary and supplies no such property. Prove Counted's counter/error ordering, actual BufWriter flush/into_parts behavior, create-new and final File synchronization. Do not require identical write-call traces between modes; relate them to the same delivered bytes under the explicit runtime/fault contract. `Delivery` is returned only after synchronize; this is a property of actual source, not a callback postcondition one may assume. [counter effects](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/output.rs:32), [B extraction and sync](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/output.rs:75), [create-new](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/output.rs:103), [mandatory B contract](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:52). ## Source that remains, and acceptance consequence

A justified modular revision could extract/prove the source contexts above and cut unchanged pure calls, avoiding whole CLI/stdlib implementation expansion. It must still account for role-sensitive entrypoint/session control: parsed/source-bound inputs and established program/ground, each actual metadata-bearing request, retention/view choice, compare and output errors, confirmed history, repeated continuation and fallback. `execute_case` validates workload/source references and establishes ground; `single_operations` loops over actual requests; `run_one_operation` invokes, compares, delivers, then checks confirmed history. These are observable ordering obligations, not incidental CLI code. Prove a loop invariant relating ground/Store/history and performed outputs, with failure at each prefix; compose step/output relations by induction over arbitrary admitted operation lists. Current pair harness has exactly two iterations, so proving it alone does not establish arbitrary repeated sessions.
