## 1. Definite compilation/API defect: `mk_app` needs the location wrapper

The proposal’s [INTRO line 47](../../../experiments/transition-study036/slice_metadata_source_v2.py:47) calls:

```ocaml
mk_app ctx.span function_expr (symbolic_value_to_texpr ctx slice_sv)
```

The owning [PureUtils.mk_app](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/pure/PureUtils.ml:632) takes `(file : string) (line : int) (span : Meta.span)` before its function and argument expressions. Consequently this call passes a span where a string is required. The existing [VaDiscriminant translation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SymbolicToPureExpressions.ml:1619) uses `[%add_loc] mk_app ctx.span ...`. The owning [PPX rule](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/aeneas-ppx/AeneasPpx.ml:13) inserts file and line for an extension, and [registers `add_loc`](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/aeneas-ppx/AeneasPpx.ml:99).

Minimal correction:

```ocaml
([%add_loc] mk_app ctx.span function_expr
   (symbolic_value_to_texpr ctx slice_sv), false)
```

This is a source-derived compilation defect, not an observed compiler diagnostic from a run in this review.

## 2. Definite omitted integration case: operand provenance still rejects metadata

The proposal changes nine source files, ending with extraction cases, but does not modify `SynthesizeSymbolic.ml` ([transformation list](../../../experiments/transition-study036/slice_metadata_source_v2.py:97)). The owning [mk_mplace PtrMetadata branch](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SynthesizeSymbolic.ml:20) still raises `Unsupported place projection: pointer metadata`; [mk_opt_place_from_op](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SynthesizeSymbolic.ml:32) sends Copy, Read, and Move operand places through it.

This is reachable outside the new operand-evaluation branch. In particular, [function-call translation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpStatements.ml:1394) computes `args_places` from the original operands **before** `eval_operands` at line 1400. [Symbolic binary operations](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:1194), [unary operations](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:1003), and [symbolic switch expansion](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpStatements.ml:952) likewise request operand provenance. **Even an ordinary `Use(Copy(...))` assignment reaches it**: [assignment synthesis](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpStatements.ml:738) obtains the RHS place at lines 754–756, and the owning [rvalue_get_place](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpUtils.ml:561) returns the place for Use Copy/Read/Move. Thus a supported metadata read can still fail after its evaluator succeeds.

Minimal correction: add a **guarded** provenance case that maps the supported shared-slice/usize metadata shape to the underlying reference’s `mplace`, similarly to [existing dereference/index provenance](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SynthesizeSymbolic.ml:18). Retain the rejecting fallback for other PtrMetadata shapes. Keep the provenance helper independent of `InterpExpressions` to avoid reversing the existing dependency (`InterpExpressions` [opens SynthesizeSymbolic](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:9)). A small type/shape classifier in a lower-level common utility, or a small duplicated guarded match, is sufficient. Do not introduce a writable metadata path.

This recommendation is **naming erasure only**, justified by the owning consumers:

- The symbolic [mplace documentation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SymbolicAst.ml:14) says it stores value-origin information to generate meaningful names; [call.args_places](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SymbolicAst.ml:63) is explicitly meta information. The Pure [mplace documentation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/pure/Pure.ml:955) gives the same purpose.
- The semantic call path first uses actual [call.args and call.ctx](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SymbolicToPureExpressions.ml:399) for consumed-borrow registration and value translation. Only afterward does it translate `args_places` and add `MPlace` wrappers. [mk_opt_mplace_texpr](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/pure/PureUtils.ml:873) wraps the existing expression, retaining its type; None returns the expression unchanged.
- The owning [pretty-name pass](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/pure/PureMicroPassesPrettyNames.ml:206) uses mplaces to register naming graph edges, including [MPlace and Assignment metadata](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/pure/PureMicroPassesPrettyNames.ml:288). These are naming relationships, not interpreter loans or alias paths. [Extraction](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/extract/Extract.ml:1602) erases all expression metadata except TypeAnnot. The new evaluator must separately retain its exact existing shared-borrow dereference and VaSliceLen equation.

The minimal justified choice is therefore a guard in `mk_mplace` returning `place_to_mplace subplace` for **only** `PlaceProjection (subplace, PtrMetadata)` with `subplace.ty = TRef (_, TSlice _, RShared)` and result usize. This preserves the existing coarse naming convention (Deref/ProjIndex/Subslice are already erased there). It does **not** identify the metadata value with the reference, dereferenced storage, backing allocation, or writable interpreter path. A possible cosmetic consequence is that the length variable inherits the slice reference’s base name; the normal name allocator remains responsible for uniqueness.

Compared alternatives: **(A)** a new metadata mprojection variant is larger than this need. Both symbolic and Pure [projection records](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SymbolicAst.ml:21), the [Pure record](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/pure/Pure.ml:946), and [translation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SymbolicToPureValues.ml:662) currently represent field projection information; adding a distinct projection requires their consumers/printers to learn it, without supplying the semantic length equation. **(B)** returning None for only supported metadata operands from `mk_opt_place_from_op` is semantically acceptable for those optional hints, but **insufficient by itself**: assignment RHS provenance calls `mk_mplace` directly. To use omission consistently, also suppress only that optional RHS place before the direct `Option.map` at InterpStatements:756 (and account for every other direct optional caller reached by the canary). Destination mplaces are required there and must not be erased by a generic fallback. The guarded naming erasure in `mk_mplace` is the smaller complete correction for the observed call and assignment consumers. Neither alternative requires any change to the actual interpreter borrow/loan machinery.

The provenance change does not authorize metadata Move: the proposal [only intercepts Copy/Read](../../../experiments/transition-study036/slice_metadata_source_v2.py:81), while ordinary [Move evaluation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:584) still uses the unsupported actual metadata place. Include a Move rejection control after changing provenance so this boundary stays explicit.

## 3. Actual type, visitor, primitive, and generic conventions

Several plausible objections are **not defects** in this pinned source:

- **No OCaml hash-cons wrapper is needed.** The owning vendored [Generated_Types.hash_consed](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/charon/charon-ml/src/generated/Generated_Types.ml:545) is an identity alias, explicitly “Not actually hash-consed on the OCaml side.” [ty and ty_kind](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/charon/charon-ml/src/generated/Generated_Types.ml:796) define `TScalar`, `TSlice of ty * trait_ref option`, and `TRef`. The proposal’s bare `TScalar (TInteger (Unsigned Usize))` is valid; baseline [discriminant construction](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:1438) does the same. `TSlice _` is a wildcard over the constructor payload; it need not bind both payload fields. It is not a nonexistent constructor or an arity defect.
- **The fresh-value APIs are used in the right order.** [mk_fresh_symbolic_value](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpUtils.ml:156) takes span, context, then type and allocates through the context’s fresh-ID function. [mk_tvalue_from_symbolic_value](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/llbc/ValuesUtils.ml:88) erases regions for the outer typed value. A usize has no region payload requiring special conversion.
- **The generated visitor follows the new aggregate automatically.** [value_aggregate and its derivation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SymbolicAst.ml:330) are mutually declared with the expression and derive the concrete `iter_expr` visitor. Adding `VaSliceLen of symbolic_value` there is sufficient for that derived visitor. The proposal also updates the owning [aggregate printer](../../../experiments/transition-study036/slice_metadata_source_v2.py:104) and [aggregate translator](../../../experiments/transition-study036/slice_metadata_source_v2.py:111). No separate handwritten aggregate visitor omission was found in the relevant source searches. This is a bounded source review, not proof that a compiler has checked every match.
- **The Pure slice representation and type argument are right.** [translate_fwd_ty](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/symbolic/SymbolicToPureTypes.ml:373) maps LLBC slices to `TAdt (TBuiltin TSlice, {types=[element_ty]; const_generics=[]; trait_refs=[]})` and erases references at line 381. The proposed Pure function has one element-type generic and one slice argument. The pinned Lean [Slice.len](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend/a0054/lean/Aeneas/Std/Slice.lean:52) has one implicit `{α : Type u}` and result `Usize`. The proposal’s [implicit argument case](../../../experiments/transition-study036/slice_metadata_source_v2.py:141) extends the existing [one-implicit-type mapping](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/extract/Extract.ml:1043), which matches that signature. Returning `monadic=false` also agrees with the existing [len builtin registration](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/extract/ExtractBuiltinLean.ml:1347), which is nonfailing and unlifted.
- **Reusing the printed name `Slice.len` is permitted.** Existing native slice len already maps to that name, but [allow_collisions](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/extract/ExtractBase.ml:398) deliberately permits `FunId (Pure _)` collisions; [registration](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/extract/ExtractBase.ml:426) puts them in the unsafe name map. This proposal does not require renaming the semantic primitive or changing its model.

The internal Pure checker is insufficient as the only generic validation: [Qualif/FunOrOp checking is TODO](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/pure/PureTypeCheck.ml:198), although [application checking](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/pure/PureTypeCheck.ml:185) checks the supplied function arrow against its argument. Actual extracted Lean elaboration is required. The model [len_val equation](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend/a0054/lean/Aeneas/Std/Slice.lean:57) supplies the intended length meaning. ## 4. Borrow preparation and multiple operands: aligned shape, bounded obligations

The dedicated evaluator’s tuple destructuring is correct: [read_place_check](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:51) returns loan option, typed value, path, and performs bottom/reserved-borrow checks. It does not return a new context to accidentally discard. [value_strip_shared_loans](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/llbc/ValuesUtils.ml:306) removes only outer shared-loan wrappers. [Shared-borrow dereference](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpPaths.ml:214) resolves through `shared_loan_value`, preserving the actual borrowed slice value rather than replacing storage with metadata.

The proposal [prepares the synthetic dereference with greedy expansion disabled](../../../experiments/transition-study036/slice_metadata_source_v2.py:75), then [re-reads it in the no-reorganization evaluator](../../../experiments/transition-study036/slice_metadata_source_v2.py:90). That matches the existing two-stage architecture: [eval_operand](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:604) composes preparation with evaluation; [eval_operands](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:611) first prepares all operands and then evaluates all without reorganization. The [CPS list combinators](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/Cps.ml:48) thread contexts and compose continuations in order. No dropped preparation context or continuation is apparent from this proposal.

Do not claim literal context immutability for preparation: the owning [read preparation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:73) can reorganize paths and loans, and [end_loans_at_place](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpPaths.ml:510) may activate reserved borrows or end mutable loans. Its Read case preserves shared loans (line 525). The dedicated metadata evaluation itself returns the same context and avoids the ordinary Copy branch’s [copy/write-back operation](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:575). That is the appropriate derived-read boundary. Later operands can still cause legitimate existing normalization; controls must distinguish this from accidental consumption or replacement of the slice/reference.

## 5. Make the declared scope fail closed in code

The helper is [called without config](../../../experiments/transition-study036/slice_metadata_source_v2.py:19) and admits any `VSymbolic` after its shape test. For the declared **symbolic-mode-only** feature, pass config and explicitly raise a metadata-specific error unless `config.mode = SymbolicMode`, before allocating a fresh symbolic result. The owning [eval_discriminant](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:1383) documents/guards that boundary, but an explicit rejection is clearer than a configurable sanity check for this narrow experiment. The existing `_ -> UnsupportedMetadataValue` already rejects concrete values; this recommendation closes the mode boundary even for a malformed concrete context containing a symbolic value. It is scope hardening, not another observed compilation failure.

Retain the proposal’s exact shared-reference/slice/usize validation and Lean-only extraction rejection. Do not accept raw/mutable/dyn metadata, concrete slice values, writes, or moves as a fallback. Global-root places also retain an existing boundary: [read-place machinery excludes globals](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpPaths.ml:308), and [access_rplace_reorganize skips globals](/var/tmp/behavior-ir-core036-v2/w001/disposable/frontend-translator-a0363/workspace/aeneas/src/interp/InterpExpressions.ml:91). If a retained canary reaches one, record the rejection; do not silently broaden this patch to global loading.
