## Smallest useful construction

Use **positive data containing an ordered list of stored key/value pairs**, with ordering, uniqueness, size and recursive-value validity stated as separate predicates. Define lookup/update/entry/iteration operations over that data, then bind the actual extraction signatures below for the concrete source key domains. This makes recursive `serde_json::Value::Object` possible without embedding comparisons, callbacks, or validity predicates inside the recursive data type. This is a prospective implementation choice, not an existing model.

```lean
-- Declaration sketch only; not compiled or checked in this investigation.
structure MapData (K : Type u) (V : Type v) (A : Type w) where
  entries : List (K × V)

structure SetData (K : Type u) (A : Type w) where
  entries : List K

structure PairIterData (K : Type u) (V : Type v) where
  remaining : List (K × V)

-- Separate definitions/theorem premises, not fields of MapData:
-- WF cmp m := strictly ascending stored keys under cmp ∧ length ≤ Usize.max
-- ValueWF v := recursively valid numbers/strings/arrays/objects and their WF
```

`A` is a phantom type parameter in this sketch: it preserves the generated type arity, not allocator behavior. Only the actual `Global` instances may initially be registered. Aeneas's own `Vec` source explicitly uses a `structure`, warning that a type alias can cause positivity trouble in nested recursive uses. Follow that precedent for both Rust map types rather than making `serde_json.map.Map` an opaque axiom or an unexamined alias. In particular, keep `WF : MapData K V A → Prop` outside the datatype: an arbitrary value predicate or an interface field consuming `V` can introduce negative occurrences even if the final field is a proof. Forward/backward functions belong to operation results, **not inside `MapData`**. Actual kernel acceptance remains work to do. [Aeneas Vec positivity comment and structure](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend-build/a0058/lean/Aeneas/Std/Alloc/Vec.lean:26).

The existing generated JSON datatype is already recursive through `Vec Value` and `serde_json.map.Map String Value`; its number representation is `PosInt U64 | NegInt I64 | Float F64`. Preserve that whole positive shape, including arrays and numbers, rather than replacing JSON with strings or natural numbers. Validity of negative integers/finite floats is a separate semantic restriction, not permission to delete variants. The owning serde source documents negative and finite invariants, with a different representation under `arbitrary_precision`. ## Operation definitions and required laws

These are actionable proposed semantics over `WF` lists; proofs and extraction support remain to be written.

1. **Lookup/insertion.** Search by the declared comparator/borrow relation. Empty lookup returns none. Inserting a new key splices it in ascending order; replacing comparator-equal `(oldK,oldV)` returns `some oldV` and stores `(oldK,newV)`. Never substitute the supplied new key for `oldK`. Prove lookup/absence, stored-key retention, unchanged unrelated entries, new-key membership and WF/size preservation. Rust expressly preserves the old key; set insertion similarly preserves an equal stored element. [map contract/implementation](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/map.rs:1020), [set contract](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/set.rs:880).
2. **Mutable lookup.** Capture a structural focus `(prefix,storedK,oldV,suffix)` when found. Return `some oldV` with a backward function updating **only that existing value** for compatible `some newV`; never search/recompare again, insert an absent key, change the stored key or remove a map entry. Absence has an identity backward function on the reachable absent branch. Specify behavior on shape-incompatible backward arguments explicitly and prove the extracted caller obeys the compatibility relation; no native deletion follows from the type `Option V → M`. The existing Slice model also returns an Option-valued backward update rather than a lookup alone. [Rust get_mut](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/map.rs:990), [Aeneas Slice get_mut](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend-build/a0058/lean/Aeneas/Std/Slice.lean:585).
3. **Entry/default.** Positive entry payloads can store prefix/suffix, stored key/value for occupied, or insertion key for vacant. `entry` returns a focus plus a backward reconstruction. `or_default` returns the existing value without evaluating Default on occupied; on vacant it evaluates the supplied fallible `Default.default` exactly once, creates occupied data, and returns a value/backward update. Compose the value-backward and entry-backward functions to restore the map. Prove no unrelated entry changes, default-call conditionality and new-key membership. The Rust source's branch distinction is explicit; the model must not eagerly call Default for occupied entries. [Rust entry](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/map.rs:1503), [Rust or_default](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/map/entry.rs:350).
4. **Iteration.** Initialize a separate cursor with the entire ordered stored list. `next [] = (none,[])`; `next (p::ps) = (some p,ps)`. Shared and owned cursors may share data-level equations but retain distinct source names and ownership/destructor contracts. `Values`/`Keys` project the same traversal; prove complete traversal, order, no duplicates/omissions, exact remaining suffix and permanent exhaustion. No reverse iterator is needed for the displayed signatures; add one only if the actual closure requires it. Rust promises key order for iter/into_iter/values/keys, and the shared map iterator forwards to iter. The borrowed set iterator similarly forwards to its ordered iterator. [Rust map ordering](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/map.rs:41), [shared map iterator](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/map.rs:1724), [borrowed set iterator](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/set.rs:1542).
5. **Clone/equality/length.** Define clone through actual admitted element clones, not an unconditional identity for arbitrary dictionaries; justify any pure-data simplification for these concrete domains. Map equality is full key/value equality, not merely key-domain equality. Convert list length to Usize under external WF, preserving overflow/failure discipline. These source operations cannot disappear because membership/update laws alone were proved. [closed clone/length signatures](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0365/generated/FunsExternal_Template.lean:596), [source canonical equality](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/views.rs:192).

## Comparator, serde backend and remaining boundary

The smallest justified initial comparator domain is the actual immutable `String` and two-String `EntityKey`, with borrowed `str`, borrowed/owned String, and identity EntityKey borrowing where actually instantiated. Establish full UTF-8-byte-preserving String/str relations and lexicographic comparator laws; for derived EntityKey ordering establish the field-order relation (entity then id) from the real derived/extracted instance. Do not add fixture-only IDs, ASCII limits, Unicode normalization, or assume arbitrary Rust `Ord` coincides with Lean equality. The built-in owning String model only annotates Lean `String`; closed String/str comparison and String-to-str borrowing are still external declarations. [Rust lexical-order/logic-error contract](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/map.rs:43), [Aeneas String mapping](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend-build/a0058/lean/Aeneas/Std/Alloc/String.lean:8), [closed str comparator](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0365/generated/FunsExternal_Template.lean:266), [closed String borrow/comparator](/var/tmp/behavior-ir-core036-v2/w001/native-extraction/a0365/generated/FunsExternal_Template.lean:764).

A list scan makes different comparisons from a B-tree search. Thus merely running an arbitrary supplied fallible comparator monadically does **not** preserve native failure/effect behavior or comparison counts. Restrict the registration to source-bound total, pure, stable lawful comparators/borrows and justify that restriction for all admitted concrete inputs; otherwise model or refine the actual search/effect protocol. The same issue applies to allocator clone, allocation/OOM, destructors and generic clones/defaults. Their erasure requires declared observation/effect justification, not a fabricated native-correctness axiom. Rust warns that changed key order can produce panic, incorrect results, abort, leaks or nontermination. [Rust ordering warning](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/collections/btree/map.rs:53), [effectful trait signatures](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend-build/a0058/lean/Aeneas/Std/Core/Cmp.lean:166).

The study manifest requests only `unbounded_depth`, and the inspected store/engine manifests request ordinary serde_json; those declarations alone do not prove the complete unified feature/cfg subject. Bind the actual selected feature/cfg closure prospectively before identifying serde operations with ordered-list BTree semantics.
