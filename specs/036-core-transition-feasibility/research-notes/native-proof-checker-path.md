# Minimal genuine T059 checker path

Research date: 2026-11-18. Read-only investigation of primary local specifications and implementation. No builds, tests, downloads, process inspection, or existing-file edits were performed. This note proposes implementation; it records no new proof result. Actual a0327 was live when this research was assigned, so its output was not interpreted as closed evidence.

## Decision

Implement one real fresh checking engine with separately selected `helper` and `native_bridge` expectations. Exercise its accepting path now with the existing extracted identity helper and its real mutants. Implement the native aggregator now, but keep its result `unestablished` while expected native root types and B01–B10 proofs are absent. A successful helper check must never populate a native bridge row or composed root. This follows T059’s explicit helper restriction and T070’s later full-closure requirement ([tasks.md:119](../tasks.md#L119), [tasks.md:130](../tasks.md#L130), [correctness.md:28](../contracts/correctness.md#L28), [correctness.md:37](../contracts/correctness.md#L37)).

Current `check_proofs.py` only trusts row status strings in `validate_obligations`, checks premises by searching for “assume”, and returns constant false from `native_verified`; it has no fresh native accepting path ([check_proofs.py:11](../../../experiments/transition-study036/check_proofs.py#L11)). The current proof contract honestly contains zero native roots, pending expected types, unestablished refinements, and required B01–B10 ([proof-contract-002.json:9](../inputs/v2/proof-contract-002.json#L9), [proof-contract-002.json:109](../inputs/v2/proof-contract-002.json#L109)). Those are missing inputs, not values to toggle.

## Proposed API and acceptance invariant

Suggested interface, not an implemented API:

```python
check_declared_proof_v2(*, context, declaration_ref, expectation_ref, out)
check_native_closure_v2(*, context, declaration_ref, native_contract_ref, out)
```

`context` is constructed by the trusted fixed executor from the declared registry, selected original/native subjects, prepared tool binding and resource profile. `expectation_ref` is independently selected by that executor and included in the frozen subject; it is never taken from a candidate result. The expectation contains an exact scope, theorem names/modules, separately authored explicit Lean types, source entrypoint/function/monomorphization identities, generated-file/import closure, and permitted foundation/external-premise contracts. It must not compute the expected type by copying `getConstInfo root`. The checker should compare explicit expected types in Lean, retaining actual type representations only as evidence.

The engine must:

1. Validate schemas, size/count/depth limits, registered roots and sealed prerequisite attempts. Verify source manifests, tool bytes and all proof/support inputs before execution and after completion. Bind the compiled native subject, extraction executor subject, and current proof-checker subject as different fields where appropriate.
2. Bind raw LLBC, actual extraction cfg, compiler/tool/options/target and all generated bytes to the selected native entrypoint closure. Recompute the LLBC inventory and compare reachable nodes/body hashes. Track trait/indirect calls, globals, types and implementations as well as direct calls. Every unresolved/opaque/native-model boundary needs a specifically justified primitive contract or checked refinement; no omitted node or target-result stub is accepted. Hash agreement is necessary provenance, not a semantic proof ([correctness.md:11](../contracts/correctness.md#L11), [correctness.md:32](../contracts/correctness.md#L32)).
3. Copy exact generated bodies into a new isolated project. Allow only individually declared support/name/type-model transformations, retaining originals and exact transformation receipts. A representation replacement remains an unestablished refinement until proved. Do not bless an edited generated algorithm because it typechecks. Current extraction already retains raw declarations, generated files and explicit open classification ([extract.py:455](../../../experiments/transition-study036/extract.py#L455), [extract.py:578](../../../experiments/transition-study036/extract.py#L578)).
4. Freshly compile; require each expected root to be a theorem with the independently specified type. Traverse all transitive axioms and actual constant/import dependencies, obtaining axiom types from Lean; reject `sorryAx`, unexpected axioms, missing roots, and unsupported opaque target-result assumptions. Compare permitted axioms against exact independently selected types (prefer Lean definitional equality with universe handling over pretty-printed string equality). Ordinary premises remain explicit at their real boundary; they cannot assume B02/B04/B05/B07/B09 or desired native equality ([correctness.md:38](../contracts/correctness.md#L38), [correctness.md:40](../contracts/correctness.md#L40)).
5. Run fresh kernel checks, recheck all input bytes, retain bounded command/audit receipts and close the owned process tree. Only successful execution creates the checked result; parsing a receipt does not create it. Replace `native_verified(report)` with the native checking entrypoint (or a wrapper that calls it), not a boolean over caller-supplied flags. Reports are outputs and never execution authority ([records.py:298](../../../experiments/transition-study036/records.py#L298)).
6. Native aggregation requires exactly B01–B10 and the independently selected B10 composed root, all for the same complete declared native subject and supported entrypoint/fallback/domain. Verify actual proof dependencies and required native refinements, rather than trusting a supplied dependency list. Helper roots have a separate namespace/result field and cannot satisfy a native slot. There is no positive native result for an empty expected-root set or partial bridge set. T069 specifies freezing the final root types/dependency inventory; T070 supplies full native mutation validation ([tasks.md:129](../tasks.md#L129)).

## Status rules

Use exactly the six obligation statuses in T059. Derive proof statuses from the engine, never from input row claims. `unestablished`: no checked required statement/closure; `in_progress`: declared partial work with remaining dependencies; `proved_for_declared_subject`: the exact obligation type/source/dependency/axiom/kernel check succeeded; `checked_conformance_only`: finite original comparisons, never a general proof; `explicit_external_premise`: precisely declared permissible environment/runtime assumption, never an automatic discharge of mandatory native refinement; `refuted`: actual counterexample/refutation of the obligation. A deliberately rejected mutant or a resource/tool failure does not refute the real native theorem. Preserve operational failure/resource-stop separately. This also removes the unsound keyword heuristic in `validate_obligations` ([tasks.md:119](../tasks.md#L119), [check_proofs.py:19](../../../experiments/transition-study036/check_proofs.py#L19)).
