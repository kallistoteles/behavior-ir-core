## Smallest justified interpretation

Use all source-valid UTF-8 strings, including non-ASCII, embedded NUL and empty strings, with the actual target's size/representation restrictions. Compare their **unsigned UTF-8 byte sequences lexicographically**. For `EntityKey`, compare `entity` first and compare `id` only when the entities are equal. Equality is exact byte equality of the string, or exact equality of both fields. Borrowing an owned String as `str` preserves the entire byte sequence; self-borrowing String or EntityKey is identity. Do not introduce ASCII-only IDs, numeric fixture IDs, normalization, locale collation, delimiter encodings, or an arbitrary user comparator as part of this initial concrete interpretation.

This is the actual key shape used by `Views`: `versions` has `EntityKey` keys; `parents`, `children` and `active` have String keys; active buckets are `BTreeSet<String>`. The source uses borrowed-str lookup in `active_children`, `owner` and `stage`, String lookup in relation seeding and apply, and EntityKey lookup/insert in apply. Active-set traversal becomes the public array order. ## Owning Rust sources

The retained analysis standard library defines `str::cmp` as comparison of `self.as_bytes()` and `other.as_bytes()`, and `str::eq` as equality of those byte slices. `PartialOrd` returns `Some(self.cmp(other))`. Its owning documentation explicitly specifies byte lexicographic order, distinguishing it from language/locale alphabetical order. [str order, equality and partial order](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/core/src/str/traits.rs:10).

Owned String in this retained source derives `PartialEq`, `PartialOrd`, `Eq`, and `Ord` over its sole `Vec<u8>` field. Vec equality compares the element slices; Vec order delegates to slice order. The byte slice specialization compares the common byte prefix and then lengths, using an unsigned-byte comparison operation. This gives the same byte sequence interpretation for owned String as for borrowed `str`, irrespective of String capacity. This is a source-level derivation, not a proved theorem about native execution. [String representation/derives](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/string.rs:350), [Vec equality macro and instance](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/vec/partial_eq.rs:6), [Vec order](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/vec/mod.rs:4368), [byte slice order](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/core/src/slice/cmp.rs:293).

## Actual Lean carriers and missing comparison

The retained Aeneas owner maps Rust `alloc::string::String` to Lean's `String` with an opaque Rust-type annotation. Borrowed Rust strings have a different carrier: `Aeneas.Std.Str := Slice U8`. `Slice` carries a length, a length-indexed list, and a `Usize.max` bound; its declaration has **no UTF-8-validity field**. `Slice.eq_iff` does establish equality iff the underlying lists agree. ## Precise proposed functions and instances

The following are mathematical definitions to implement and prove, not checked Lean declarations. Let `bytesS(s)` be the complete list of numeric values of `s.toByteArray` bytes; let `bytesQ(q)` be the numeric values of `q.val : List U8`. Define a structurally recursive, pure `lex8`:

```text
lex8([], [])           = eq
lex8([], y::ys)        = lt
lex8(x::xs, [])        = gt
lex8(x::xs, y::ys)     = lt if x < y; gt if y < x; lex8(xs,ys) otherwise

cmpS(s,t)              = lex8(bytesS(s), bytesS(t))
cmpQ(q,r)              = lex8(bytesQ(q), bytesQ(r))
eqS(s,t)               = decide(bytesS(s) = bytesS(t))
eqQ(q,r)               = decide(bytesQ(q) = bytesQ(r))
eqSQ(s,q)              = decide(bytesS(s) = bytesQ(q))
cmpE(k,l)              = cmpS(k.entity,l.entity), unless eq, then cmpS(k.id,l.id)
eqE(k,l)               = eqS(k.entity,l.entity) && eqS(k.id,l.id)
```

Wrap each concrete equality/comparison result in `Result.ok`; define PartialOrd as `ok (some cmp)` and its Boolean operations consistently. For String-to-Str borrow define `borrowSQ(s)` to return `ok q` with `bytesQ(q) = bytesS(s)`, using the source-related size proof. For String-to-String and EntityKey-to-EntityKey borrowing return `ok` of the original value. Do not pretend the two different carriers make String-to-Str identity. Define `SourceString(s)`/`SourceStr(q)` separately from the map data: UTF-8 validity and actual target bounds, with a representation relation to the source bytes; EntityKey validity is componentwise. The implementation must handle the helper's proof/bound mismatch explicitly rather than supplying an unproved bound.

Initially account for these concrete source instances only:

| Stored key K | Query Q | Proposed order/borrow |
| --- | --- | --- |
| String | String | `cmpS`, self-borrow identity |
| String | Str (`&str` source query) | `cmpQ` on queries; byte-preserving `borrowSQ` on stored keys |

Keep String/str cross equality for the actual source comparisons too; it is not itself a map query-order dictionary. Add further instances only when their real source uses and owners are established. Rust's Borrow contract demands equivalent Eq/Ord behavior, and BTreeMap explicitly requires borrowed order to match stored-key order. Search compares **query against borrowed stored key** (`key.cmp(k.borrow())`), so preserve that argument direction or prove the reversal used by the model. ## Remaining obligations and controls

1. Prove `lex8` terminates, reflects list equality at `eq`, is antisymmetric under reversal, is transitive and total, and has the stated empty/prefix behavior. Lift these laws to cmpS/cmpQ/cmpE, including exact EntityKey field equality. `Slice.eq_iff` can discharge the Str carrier-equality step; String byte-encoding injectivity still needs an owning theorem or a local proof.
2. Prove byte preservation, UTF-8 validity and size preservation for all admitted conversions, clones and borrows. Prove `cmpQ(borrowSQ(s),borrowSQ(t)) = cmpS(s,t)` and the corresponding Eq law, including mixed source query/store relations. Establish `eqS` agrees with the actual String Eq dictionary before replacing it by Lean equality. No such full bridge lemma was found in the inspected model owners.
3. Bind each admitted concrete Rust instance and its extracted dictionary to these functions. Prove every admitted comparison/borrow is exactly `ok` of the pure result, with no fail/divergence or observed state change. Aeneas `Result` permits both failure effects and divergence; merely taking an Ord/Borrow record does not prove their absence. A list scan can then differ from B-tree comparison counts only under the separately established observation contract. Arbitrary fallible/stateful dictionaries remain outside this shortcut. [Result definition, ok, fail and div](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend-build/a0058/lean/Aeneas/Std/Primitives.lean:51).
4. Separately establish the relation between the selected native Rust 1.98 subject and the retained analysis-toolchain source subject (identified by the task as analysis 1.100), including derives, target/cfg/library choice, byte intrinsics and source/string representation. This investigation did not inspect a Rust 1.98 owning std source or prove any compiler/library relation. Stable annotations in analysis source are not that proof. Do not replace this work with a global proof-equivalence assumption or native-correctness axiom.
5. Preserve the map/set operation obligations in the interface note, especially stored-key retention, sorted traversal and mutable value-only reconstruction. Concrete comparator laws alone do not prove any collection algorithm or native admission.
