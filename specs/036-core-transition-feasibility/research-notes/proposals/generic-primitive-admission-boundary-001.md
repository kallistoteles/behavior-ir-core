# Minimal generic primitive boundary for actual String/JSON callers

Research only, 2026-11-21. **New, unselected note.** Read only the permitted contract/proof-contract, named proposal/feature records, actual reference/views/eligibility sources, and four named dependency models. No builds, tests, private reads, discovery, selected/private writes or status changes. This note proposes an admission criterion and the next source relations; it establishes neither primitive admission nor native correspondence.

## Concrete boundary decision

The admissible candidate is **a source-bound interpretation of the listed concrete library APIs over complete byte/JSON data, with explicit normal-return and effect guarantees**. It may trust ordinary compiler/runtime/library correctness at that narrow boundary rather than formally proving allocator, byte intrinsic, Clone derive or B-tree balancing internals. The interpretation must be independently justified and visible, and actual Core callers must still prove that their inputs, dispatch, branching and updates satisfy it. This follows the contract's explicit generic-runtime-primitive alternative and its prohibition on concealing projection/evaluation/observation equality in runtime assumptions. The contracts do not themselves automatically approve a new primitive or prescribe a complete mechanical admission test. [permitted classification and ordinary assumptions](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:30).

The following are legitimate **kinds of ordinary generic API premises**, provided pinned owners/configuration and their observation scope justify them. They do not mention Parent/Child, finish, Store history, projection or a desired Core result:

| Concrete API | Candidate trusted library guarantee, independently specified |
| --- | --- |
| String.as_str and Value.as_str | On valid represented input, borrow exactly the original UTF-8 bytes without mutating the payload; Value returns Some only for its String constructor, otherwise None. Native accessor borrowing is not native String-buffer copying. |
| String.clone and str.to_owned | On normal return, preserve every byte and the original data while supplying the appropriate owned result; copy/ownership, resource and drop behavior belong to the declared runtime contract. They are separate APIs, not identical native call paths. |
| Full Value.clone | On normal return, preserve the entire represented recursive payload: all six variants, exact Number payload, String bytes, array order/multiplicity and object key/value/order data. No phase/owner-only projection or Nat-only reduction is permitted. |
| JSON Map.new/insert | New normally represents empty content; insert normally returns the previous value or absence and performs exactly the feature-bound key update, preserving unrelated entries, stored-key/order rules and valid representation. This abstracts backend layout, not the caller's choice of keys/values. |
| Read-only JSON Index / Value index | The concrete sealed string instance performs exact field lookup; non-object or missing key is absence, and ordinary Value indexing maps absence to Null. Shared-reference forwarding and Value indexing dispatch exactly once through the actual underlying field/dictionary, preserving its applicable outcome. |

These facts can be ordinary explicit **generic library interpretation premises** under the permitted option; they need not each be disguised as a formal proof of native stdlib internals. Their defined Lean models still require general independently specified content/frame/domain laws, exact source-name/signature binding and controls. Conversely an identity clone `rfl` theorem only proves a chosen model equation; it does not justify the library interpretation. Current scalar, map and index modules explicitly retain this distinction. [scalar interpretation disclaimer and definitions](/data/repos/behavior-ir-core-033/experiments/transition-study036/proofs/Correspondence036/Dependencies/NativeJsonScalarOperations.lean:8), [map interpretation disclaimer](/data/repos/behavior-ir-core-033/experiments/transition-study036/proofs/Correspondence036/Dependencies/NativeJsonMapOperations.lean:8), [index interpretation disclaimer](/data/repos/behavior-ir-core-033/experiments/transition-study036/proofs/Correspondence036/Dependencies/NativeJsonIndexOperations.lean:8).

“Core's selected row is interpreted correctly,” “views equal canonical state,” “the original evaluator has the same first error,” or “both whole programs have equal observations” are **not** ordinary primitive premises. They are precisely mandatory source relations. Nor can an arbitrary representation predicate or callback be defined to return those desired answers. The proof-contract explicitly leaves external refinements unestablished and disallows assumed desired projection/observation equality. ## Allocation outcomes must remain distinct

Content correctness on **normal return** is a useful legitimate generic premise even when allocation can fail. It does not establish the current model's unconditional `.ok` behavior for every actual execution. Use the following outcome policy in the dossier rather than calling all failure forms “Result error”:

- **Returned errors/absence:** preserve the actual return type and first returned error. The Option returned by Map.insert denotes prior membership; as_str's None denotes a non-string; field lookup's None denotes absence/wrong container. They are not allocation failures. The caller subsequently turns selected absence into its own SeedIdentity/Field error or selector failure, and that choreography requires an actual-source proof.
- **Allocation abort:** an abort has no normal return. It cannot be represented as `ok`, `Option.none`, a fabricated native error, or the model's invalid-input `.undef`/size guard. If the declared observation includes termination/delivery/performed effects, model the relevant abort outcome and retain effects already performed, or explicitly justify an environmental premise excluding it for the entire claimed execution scope. Two algorithms with different allocation schedules cannot be assumed to abort together merely because their successful values agree.
- **Panic/unwind:** bind the actual allocator and panic mode/hooks/catching boundary. A mutation before a later unwind must be preserved if the caller/environment can observe the mutated state. If a declared environment excludes unwinding, justify and enforce that exact scope; do not infer it from an unchecked assumption or missing catch in these few files. A coarse `.fail .panic` is not automatically a contract for message, hook, unwind, cleanup or process-abort behavior.
- **Drops and recursion/resource use:** justify abstraction of the concrete standard payload/drop/deallocation paths and any allocator hooks at the selected endpoint. Full recursive Value clone/drop may require stack as well as heap resources; source-valid finite data does not itself prove every recursive operation completes. Ordinary runtime/resource assumptions may be explicit, but neither a pointer-free model nor an identity clone proves their satisfaction.

An RSS/process/cache cap is a measurement/controller bound, **not allocator success, reserved heap, sufficient stack, matched OOM behavior, or a bound on all admitted inputs**. A bounded peak observation from one run would not prove those facts either. Do not convert the feature's arbitrary finite representable domain to fixture/measurement limits. [domain and complete outcomes](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:5), [ordinary assumptions at their boundary](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:40).

For allocating APIs there are two honest routes: (a) admit normal-return content semantics with a separate, independently justified/enforced resource/no-unwind premise strong enough for the claimed theorem, or (b) use an outcome/world abstraction that represents the applicable unsuccessful execution and prior mutation. If neither route is closed, normal-return component relations can still be proved and labeled conditional; they do not prove full B10. No new source refusal or selector narrowing is authorized by this choice. [existing allocation distinction](string-primitive-admission-plan-001.md:71).

The Null-to-object issue is concrete: current index_or_insert constructs the Object only in its successful backward closure, and its own disclaimer says mutation on a failing key-copy path is not modeled. The preceding review records the native order: Null changes before eager to_owned/entry lookup. That model cannot presently serve as a general unwind-state primitive, even though its successful data equations are plausible. [current modeled staging](/data/repos/behavior-ir-core-033/experiments/transition-study036/proofs/Correspondence036/Dependencies/NativeJsonIndexOperations.lean:52), [specific source review](native-json-index-source-review-001.md:32).

## The smallest admission predicate/dossier

Use the following as a **prospective review predicate**, not a new Lean axiom, an implemented status Boolean or permission to change a flag:

```text
AdmitAt(operations, exactTuples, domain, observations, E) :=
  exact source/item/feature/compiler/model/extraction binding
  ∧ independently specified generic value/ownership/effect contracts
  ∧ explicit justification of ordinary compiler/runtime/library trust
  ∧ general checked model laws under a concrete representation relation
  ∧ applicable return/abort/unwind/drop/resource outcomes covered by E or model
  ∧ actual caller proofs establish/preserve the domain and reachable dispatch
  ∧ fresh expected-type/axiom/source/control closure for the declared scope
```

One small dossier should contain: the exact operations and reachable dictionary fields; native/analysis source and tool identities and known differences; final serde feature/unit facts; complete byte/Number/recursive-JSON/map validity relation; normal-return API and frame contracts; the explicit outcome/allocator/panic/drop observation policy; ordinary assumptions and their scope/justification; model root types and transitive dependencies; actual caller/domain roots; and retained positive plus source/model/type/feature mutant controls. The trusted API guarantees must remain uniform over their whole source-valid domain and reusable by unrelated clients. Do not put any Core projection/evaluation equality in this record.

A concrete representation relation may abstract a valid native String to its complete initialized UTF-8 bytes, or a source Value to all of its recursive payloads. Those low-level memory/ownership interpretations may be part of the declared generic runtime boundary. The **actual application-specific connection**—which row/key/field/history/context was supplied, which constructor branch ran, which owned copy was inserted, and how it relates to a ChildRow—must be proved by the actual caller code. An unrestricted `representationIsCorrect` callback or an input premise already saying the two output projections agree would not meet this criterion.

For the immediate projection component, narrow the admitted Index scope to **read-only str/shared index_into and Value.index**, if the actual source/dependency audit proves those are the only called/escaping fields. The provided reference/text callers use shared `v[key]`, and materialize inserts into JSON maps; they do not invoke JSON mutable indexing in the shown bodies. Keep the complete generated Index dictionary definitions and honest dependency classifications. Prove field-level reachability/no escape rather than deleting mutable fields or claiming a three-method native dictionary contract. If the proof context instead requires all mutable methods' semantics, close their compatibility and failed-mutation obligations before such broader admission. [actual read-only callers](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/reference.rs:38), [text caller](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/views.rs:54), [materialization](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/views.rs:204).

## Actual caller relations still to prove

The next proofs should use the admitted generic value contracts to derive these source-specific facts, rather than assume them:

1. **Input/representation preservation.** Construct the relation from the actual Store/export/version and String/JSON representations; prove exact key bytes, valid bounds, full Number/array/object payloads, sorted unique BTree keys, and valid borrows at every call. Freshly generated caller bodies and dictionaries must match those reviewed. Current borrow/accessor successes rely on explicit model bounds, and invalid-key decoding is only an off-source totalization. [String operation domain premises](/data/repos/behavior-ir-core-033/experiments/transition-study036/proofs/Correspondence036/Dependencies/NativeStringOperations.lean:110), [index decoding/read-only model](/data/repos/behavior-ir-core-033/experiments/transition-study036/proofs/Correspondence036/Dependencies/NativeJsonIndexOperations.lean:17).
2. **Canonical row result and error order.** `state_fact_row` reads/as_str-converts/copies id **before** checking entity. It then clones the complete phase or owner JSON into the selected accumulators. Derive that exact update, parent/child framing, new/replacement behavior and first SeedIdentity/UnexpectedEntity result from its actual body. Trusting clone/lookup does not choose the right entity/key or prove that update. [canonical source](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/reference.rs:38).
3. **Typed-view relationship and constructor/accessor laws.** `views.text` requires a string field and returns Field otherwise; seed_row checks id/entity, phase sets, ownership and lifecycle through the subsequent relation pass. Canonical reconstruction can clone a non-string phase/owner where typed view seeding fails. Therefore prove the matching-row relation from the actual successful seed checks; do not assume all malformed rows have equal errors or that the views are already canonical. `child_entity_value` creates id/owner/phase, while materialize emits owner/phase and uses fresh empty field maps. Prove these distinct actual constructions and their agreement under an independently defined input relation. [text and seed checks](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/views.rs:54), [ownership/lifecycle relation](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/views.rs:106), [constructor](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/views.rs:138), [materialize](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/views.rs:204).
4. **Actual selector, continuation and observations.** `eligibility.finish` checks module/policy, trusted history, overflow, request format/capability, empty input/context, binding shape/entity/id and stage, then copies the child. Derive its successful domain and its actual original-fallback behavior; do not use a library premise saying the request is eligible. Stage/apply/history/authority, Store export/version correspondence, all eight observations and the rest of B01–B10 remain mandatory and require exact source composition. [selector source](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/eligibility.rs:16), [stage source](/data/repos/behavior-ir-core-033/experiments/transition-study036/src/views.rs:221), [full contract](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:15).

The immediate actionable result is a pair of actual-row/component theorems under explicit byte/JSON input relations and a justified library/outcome interpretation, followed by whole-fold/seeding/promotion composition. Generic API premises can state content preservation and exact lookup/update behavior; they cannot provide those row theorems. Same-function congruence applies only after actual complete arguments, dictionaries and performed conditions are proved equal, not to clone versus to_owned call paths.
