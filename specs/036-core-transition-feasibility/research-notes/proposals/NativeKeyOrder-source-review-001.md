**No definite syntax, type or theorem-name defect was identified in the reviewed draft.** In particular, the following potentially delicate steps agree with the owning declarations:

- **Bit-exact byte wrappers, draft lines 17–23.** Aeneas `UScalar` has exactly one `bv : BitVec ty.numBits` field; `UScalarTy.numBits .U8` reduces to 8. SDK `UInt8` has exactly one `toBitVec : BitVec 8` field. The anonymous constructors and `cases byte; rfl` inverse proofs match these representations. This establishes the mathematical wrapper inverses, not equivalence of external/native integer runtimes. [Aeneas width and carrier](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend-build/a0058/lean/Aeneas/Std/Scalar/Core.lean:50), [U8.bv specialization](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend-build/a0058/lean/Aeneas/Std/Scalar/Core.lean:1107), [SDK UInt8 carrier](/var/tmp/behavior-ir-core036-v2/w001/analysis-lean-install/a0051/sdk/lean-4.36.0-rc2-linux/src/lean/Init/Prelude.lean:2573).
- **Borrow and Str inverse, draft lines 25–43.** `Str := Slice U8`. `Slice.from` takes the actual list-length/Usize bound, and `[simp] Slice.from_val` exposes precisely the list used to construct it. `Slice.eq_iff left right` is `left = right ↔ left.val = right.val`, so using `.2` to prove Slice equality is the correct direction. Mapping the byte inverse over the assumed equality is enough mathematically; the draft's map-composition simp route matches these source equations. The draft avoids both the old helper's U32 restriction and its distinct ByteArray.toList loop. The boundary remains material. `cmpStr` defines lawful byte comparison for **all** Str inhabitants, including invalid UTF-8; Slice's carrier has no UTF-8 predicate. That general mathematical definition is sound, but a native Rust-str relation must restrict reachable values to valid UTF-8 and preserve exact bytes. The current borrow function supplies an explicit Usize bound rather than deriving one for every Lean String. Source-valid String/EntityKey domains still require the selected target's representation/allocation restrictions, potentially stronger than the Slice bound. Neither byte inverses nor comparator laws supply those source-domain facts. [Slice representation](/var/tmp/behavior-ir-core036-v2/w001/analysis-backend-build/a0058/lean/Aeneas/Std/SliceDef.lean:15), [actual Rust String validity](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/string.rs:114).

For a later operation model, record the relation `borrowedBytes q = ownedBytes s` plus UTF-8/domain validity, prove that actual String/str and EntityKey dictionaries implement these comparisons and borrows with the required Result/effect behavior, and preserve the Rust 1.98/analysis 1.100/native bridge obligations. No dictionary registration or native adequacy theorem follows from this draft. If uniform comparator-law interfaces require separate Str reversal/reflexivity/totality declarations, those wrappers are not presently named in this draft; the existing SDK List laws and `borrowedBytes` projection provide the mathematical route. Their absence is coverage work, not an identified type error in the existing declarations.
