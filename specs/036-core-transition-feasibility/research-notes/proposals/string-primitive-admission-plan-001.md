## Domain and representation relation

Use the existing model views `ownedBytes s := s.toByteArray.data.toList` and `borrowedBytes q := q.val.map toLeanByte`, whose U8↔UInt8 wrappers preserve all eight bits. Compare lists with the pinned SDK's unsigned UInt8 lexicographic comparison. String equality must be proved equivalent to `ownedBytes` equality; Str equality to `borrowedBytes` equality. The code already supplies the byte conversions, borrowed injectivity and comparison/equality/coherence laws. [byte views/conversions](/data/repos/behavior-ir-core-033/experiments/transition-study036/proofs/Correspondence036/Dependencies/NativeKeyOrder.lean:17), [order/equality laws](/data/repos/behavior-ir-core-033/experiments/transition-study036/proofs/Correspondence036/Dependencies/NativeKeyOrder.lean:53).

Define a concrete source relation using native heap/slice payload bytes, lengths, ownership/liveness and the selected target, not a predicate whose meaning is a desired Core result. At minimum:

```text
ByteDomain_T(bs) := valid UTF8(bs) ∧ length(bs) ≤ isizeMax_T
                   ∧ length(bs) ≤ usizeMax_T

RepOwned_T(nativeString, s) := source heap/vector validity and ownership
                              ∧ its exact initialized payload bytes = ownedBytes(s)
                              ∧ ByteDomain_T(ownedBytes(s))

RepBorrowed_T(nativeStr, q) := source slice validity/lifetime/read permissions
                             ∧ its exact payload bytes = borrowedBytes(q)
                             ∧ ByteDomain_T(borrowedBytes(q))
```

These are specification schemata to define at the admitted memory abstraction boundary; no concrete native heap semantics is fabricated here. A lawful relation must preserve exact bytes, not just character count, formatting, Unicode normalization or fixture ID interpretation. Include arbitrary finite source-valid UTF-8, empty strings, NUL and every admitted native key/context/JSON string. Pointer/capacity/resource identity can be abstracted only after checking that these nine operations' clients do not observe it; that is a generic API observation restriction, not permission to simplify Core rows/context. Both source versions' Vec slice contract explicitly records the isize byte-size restriction. [source bound comparison](native-analysis-string-contracts-001.md:29).

Lean String already carries SDK UTF-8 validity but is not globally Aeneas-Usize-bounded. Aeneas Str already carries the Slice Usize bound, but permits invalid UTF-8. Current `ValidStr q` tests the converted bytes' validity; current `valid_iff_owned_bytes`, `decode_bytes`, `decode_bound`, `borrow_decoded`, `decode_comparison` and `decode_borrow` give the appropriate conversion relations. Add the useful general success equivalence `ValidStr q ↔ ∃ s, decode q = some s`, if not already in the final closure; derive it from the pinned checked decoder. If the current Result interface cannot express an outcome required by the endpoint, repair that interface or retain S05 as unresolved. ## Genuine controls and execution order

The next implementation sequence is: freeze nine-operation/source/domain/effect dossier and expected types; close the justified runtime assumptions or model missing effects; add general byte refinement/domain-preservation roots; integrate only the nine exact registrations; regenerate/bind real consumer closure; then run fresh positive and mutant checker controls. No execution is authorized or performed by this note.

Required controls should exercise real rejecting paths and retain both successful and expected-failure receipts:

- **Semantic model mutants:** reverse cmp, use signed bytes, length-first comparison, collapse NUL/prefix or normalized spellings, return None from partial_cmp, replace equality with constant true, borrow truncated bytes or decode a different owned value. Fixed expected general byte roots must reject each applicable mutant; the expected specification must not be regenerated from the mutant.
- **Domain controls:** valid empty/non-ASCII/NUL/prefix/normalization-distinct strings pass the intended equations; an invalid UTF-8 Slice (e.g. `[0xff]`) exercises ownResult's declared failure without being called a native Rust-str input. Check bound-dependent borrowing by general proofs and a separately justified small-bound generic test abstraction; no impossible giant allocation or native-domain claim is needed to witness the guard logic.
- **Binding controls:** change a selected Rust owning body and rebuild/re-extract a declared canary, substitute native/analysis source or cfg, alter registration item/signature/dictionary or leave a dependency unregistered. The real source/manifest/extraction checker must reject the mismatch; a model theorem alone cannot detect a trusted API being attached to different Rust code. [required source mutation control](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:70).
- **Proof controls:** remove a root, weaken a domain/effect premise, change an expected type, introduce a forbidden axiom or substitute a stale generated file. Require actual rejection against the real checker, alongside a positive unchanged subject. A permanently rejecting guard and edited report flags are not controls. [control requirement](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/contracts/correctness.md:77).
- **Effect controls where modeled:** allocation failure/abort and any admitted clone/drop/allocator effect must follow the declared outcome contract and never become success. Where the interpretation instead assumes availability/unobservability, test the checker rejects an instance/endpoint outside that declared scope; such controls test scope enforcement, not prove runtime assumptions.

The current finite Unicode/prefix/normalization/EntityKey tests are useful witnesses, not substitutes for general roots. EntityKey field-order/collision controls concern a separate derived instance, and collection iteration/retention controls remain mandatory when those primitives are admitted.
