## Deterministic closure and transformation specification

Freeze the two roots and their expected universal types independently of the producer. Inventory the complete elaborated dependency closure `C` through both declaration types and values, recursively including all inductive-family members and mutually recursive groups; include explicit records of generated auxiliaries and operation-model dependencies. This is a required future read/check step, not an executed operation in this research.

For each declaration `d` in `C`, compute a carrier footprint `D(d)` as the least fixed point over elaborated constant references:

- The JSON carrier has footprint `{J}`; the I/O carrier has `{I}`.
- A declaration inherits the union of the footprints of references in its type and value. References include constructor, recursor, projection and auxiliary constants; mutual groups are treated atomically.
- Datatype-generated declarations inherit the footprint of their whole parent family, even if a particular constructor has no payload mentioning one parameter. For example `Prerequisite` still constructs `StudyError J I`.
- Carrier-independent declarations retain no new parameters. Reject any undeclared external or unsupported dependency discovered during traversal; the two supplied carrier names are not a license to generalize arbitrary axioms.

The selected closure contains prerequisites that are independent of the carriers. Reuse those definitions unchanged only after an inventory check proves that their types and values do not mention either old carrier or a carrier-dependent old constant. Otherwise copy and transform them using the same rule. Freeze the original complete module inventory and a `selected`/`unselected` decision for each declaration; skipping an unused declaration must not become an unsupported claim about the original full call closure.

Generate the transformed closure in disjoint module/namespace names to avoid old/new resolution collisions. Define `tau` on elaborated expressions: replace the two carrier constants with the corresponding bound variable, and replace a dependent reference `d` with its renamed parametric reference applied to the ordered footprint arguments (`J` then `I`). Recurse homomorphically over applications, binders, lets, literals, projections, and other supported expression forms, preserving binder order, original arguments, branch order and literals. Adjust de Bruijn indices correctly when inserting leading binders. Reject unsupported forms or unmatched references instead of guessing.

For each non-inductive dependent declaration, its proposed new type is `∀ (footprint parameters : Type), tau(oldType)` and its value is the corresponding lambdas around `tau(oldValue)`. For inductives/structures, reconstruct the whole family with uniform leading parameters and translated constructor/field types, then obtain the new constructors, recursors and generated declarations from Lean. An independent checker must validate those generated members against the declared family transformation, not trust an assumed name-for-name recursor mapping. This is especially relevant to custom Aeneas attributes/elaboration; whether all attributes work unchanged on generalized datatypes is untested here.

Source generation may use explicit named carrier arguments for readability, but semantic conservation must be checked on elaborated expressions, not achieved by textual replacement or assumed implicit inference. A bare final theorem binder, a `section variable` that is never included, or an unbound implicit metavariable does not count. Every occurrence of `StudyError`, `StudyError.Prerequisite`, the `FromSame` type argument, and the final root's `state_fact_row` reference must point to the same ordered pair. Retain fixed `Type` parameters initially, matching the exact original carrier sorts; unnecessary universe generalization expands the checking problem.
