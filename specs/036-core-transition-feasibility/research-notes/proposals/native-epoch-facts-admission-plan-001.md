## Minimal identity-aware generic runtime primitive

Use a process/session-local abstract allocation store with fresh generation identities, strong handles and live borrows. A handle represents `(allocation identity, payload relation, ownership share)`; an allocation identity is not the payload or a persistent physical address. The minimal normal-return laws are:

1. `Arc.new(v)` allocates a fresh live allocation, stores a related payload and returns one strong handle. Distinct simultaneously live allocations have distinct storage. Even `Arc<()>` is allocation-bearing through its Arc header.
2. `Arc.clone(h)` returns another strong handle to the same allocation and preserves the payload relation; it changes ownership/refcount state. It is not the identity function on the entire runtime state.
3. `Arc.ptr_eq(h₁,h₂)` on valid live handles returns allocation-identity equality and does not evaluate payload equality. It preserves both handles. Generic dyn-Arc metadata is ignored by this API; it therefore cannot prove equal vtables.
4. Valid dereference/borrow exposes the same related allocation payload for the borrow's lifetime, with Rust aliasing rules enforced. Mutation through `Arc::get_mut`, `make_mut`, raw reconstruction, interior mutability, or Weak upgrades needs a separate operation inventory/model if reachable.
5. Dropping a handle removes that ownership share; the last strong drop runs the payload destructor. An address may later be reused, but the abstract allocation generation changes. No operation accepts a stale or forged handle. The actual private epoch payload `()` has no user destructor effect; enclosing results/facts have separate drop obligations.
6. For the `MatchedParent` seam, `std::ptr::eq` on valid simultaneous `&Module` borrows reflects the same addressed module location under the actual borrow relation. The exact `Module` content match remains an ordinary source check, not this primitive's postcondition.

The analysis Arc owner states shared allocation and strong lifetime, implements `ptr_eq` by `ptr::addr_eq`, increments strong ownership on clone, aborts at the refcount guard, and drops the value after the last strong decrement/acquire synchronization. [sync.rs:83](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/sync.rs:83), [sync.rs:2256](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/sync.rs:2256), [sync.rs:2521](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/sync.rs:2521), [sync.rs:2983](/var/tmp/behavior-ir-core036-v2/w001/analysis-toolchain/a0039/sysroot/lib/rustlib/src/rust/library/alloc/src/sync.rs:2983). These justify the proposed law shape; they are not a checked native refinement or a proof of source caller invariants.

The dossier must state allocation success, bounded reference-count behavior, memory safety/allocator validity, atomic synchronization and destructor/unwind conditions at the actual native boundary. An allocator abort or refcount abort is not a returned `StoreError`, `None`, or DENY. A resource/RSS cap is not an allocator-success proof. Either enforce the successful-call environmental domain with a justified native boundary, or extend the observation/effect relation to nonreturning outcomes; do not grant authority after an abort/unwind. Likewise preserve the actual mutex behavior: `validation_cache` maps poison to an error, `prepared_for` treats lock failure as no prepared candidate, `retain_checked` quietly skips retention, and explicit revocation recovers/clears poison. [store.rs:1478](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-store/src/store.rs:1478), [store.rs:1541](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-store/src/store.rs:1541), [store.rs:1282](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-store/src/store.rs:1282).

## Concrete admission dossier and remaining proof roots

The smallest defensible predicate is a conjunction, not a desired evaluator equality:

`PrimitiveBoundary(subject, E) := ExactSourceAndCfgBinding(subject) ∧ ValidMemoryAndLifetimes(E) ∧ ArcOperationContracts(subject,E) ∧ ExactFixedMethodDispatch(subject,E) ∧ ExplicitAbortUnwindAndSynchronizationPolicy(E)`.

It grants only generic memory/identity/call behavior. Separately prove, over arbitrary finite source-valid inputs, the following actual roots:

- **Allocation/borrow relation:** each reachable Arc new/clone/deref/compare/drop and module pointer comparison refines the above model; handle identities are not erased by extraction, equality of `()` is never epoch equality, old strong ownership spans every comparison, and no forged/imported handle enters. Bind native stdlib/compiler/target/allocator and analysis relation prospectively.
- **Store certificate relation:** successful full validation/initialization creates exactly the actual facts/canonical module/schema/history relation; cache reuse preserves it; prepared facts correspond to that same certificate; `prepared_for`/`retain_checked` keep the allocation relation under cache replacement/poison. The actual finite JSON/key/UTF8/Usize domains and collection refinements remain prerequisites.
- **Prepared epoch transition relation:** checked construction and module matching establish only their proved invariants; child rows/typed/templates equal the actual transition's result; `apply` preserves these and advances to a fresh epoch only after the correct confirmed carry. No premise may simply assert that prepared evaluation equals original evaluation.
- **Facts method relations:** fix the actual Capture/Backend monomorphizations and each concrete vtable; prove each reachable method/default, its backend state position, ordered traversal, full returned payload, first error and fallback. Then prove the direct prepared count/query/row-template optimizations preserve actual original observations. Retain history-only `used` failures and lifetime queries.
- **Writer/session relation:** prove every mutable-backend/writer-change/restart entrypoint revokes or reestablishes the correct certificate; prove private Capture ownership excludes unsynchronized external mutation under the declared host model; prove no persisted packet/provenance/result can revive a live token. Address reuse after process exit grants no cross-session authority.
- **Confirmation and composition:** prove actual CAS/ack semantics, incremental carry body and Ground maintenance for Applied, conflict, precommit error, unknown/lost ack, delivery failure and subsequent continuation. A stale result may stay memory-live without staying semantically authoritative. Full B01–B10 composition remains required.
