# Native Facts congruence route for B05/B06 — source-only proposal

Scope: this note records source facts and prospective proof/refactor obligations only. No implementation, execution, extraction, proof checking, acceptance decision, or changed claim is supplied. The contract requires exact native operations/errors/commands (B05), actual Safety projections and preservation (B06), and congruence only for the same actual function with equal complete arguments and compatible performed errors/effects. [Contract:21–22,42–44](../../contracts/correctness.md#shared-original-function-congruence). T064/T065 remain separate obligations. [Tasks:124–125](../../tasks.md).

**Finding:** the smallest useful route is concrete provider/snapshot acquisition relations plus narrow shared original clients; there is no complete-argument congruence shortcut across the current fresh/prepared evaluator calls. A small wrapper can expose genuinely shared envelope or Safety-inspection calls, but cannot silently make prepared evaluator equality, row-template replay, or inherited Safety validity external premises. This is the deduction from the distinct arguments/branches below, under [the contract's dependency/refactor rules:32–40](../../contracts/correctness.md).

## Facts equality: sufficient premises and forbidden leaps

The dynamic interface has six methods: `exists,used,incoming,query,field,entity`. `QueryRequest` includes actual module, query node, definition, instance, captures and typed environment, and invokes original `query_matches(module,node,env,candidate)`. A method-response relation must include these complete query arguments; matching instance hashes alone is not it. [C/facts:42–85](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/facts.rs:42).

Concrete `Facts` derives equality over all six maps (existence, historical identities, references, queries, fields and universe). Full equality of those native fields plus equal complete method arguments, same actual impl/client source, and compatible runtime conditions suffices for congruence of **that concrete call**. Equality of only universe is weaker: explicit existence/field/query entries override or constrain lookup, and `used` reads the historical identities map. [C/facts:102–115](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/facts.rs:102), [C/facts:126–208](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/facts.rs:126). This does not establish a theorem about every client of arbitrary `&dyn EvaluationFacts`.

`SnapshotFacts` current-state calls delegate to `SeedFacts`, but `used` calls the backend at its recorded position; absent entity/field results use Store-specific error strings. `StoreFacts` additionally performs backend existence/incoming/version/index/query operations. Substituting plain `Facts` is therefore a source refinement, not trait-object identity. [S:984–1018](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-store/src/store.rs:984), [S:855–912](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-store/src/store.rs:855).

The ordinary evaluator captures a complete provider snapshot and normalizes/checks it; prepared evaluation instead validates bindings against parent facts. Internally the same `ValidatedProvider` impl reads state from `Supplied` and history-only `used` from the original provider, but its state input is fresh normalized facts versus prepared parent facts. [C/eval:2762–2809](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:2762), [C/eval:2914–2937](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:2914), [C/eval:4478–4552](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:4478). Required acquisition proof must follow `provider_snapshot`: query every entity type; sort/reject duplicate IDs; entity read with field fallback on error; decode/check identity; then complete normalization/behavior validation. Equal successful rows does not preserve these performed failures automatically. [C/eval:4554–4607](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:4554), [C/eval:4483–4521](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:4483).

Even exact fresh/parent `Facts` equality is insufficient for evaluator congruence: prepared control changes select-member acquisition, count execution and complete-child checks. Untouched rows can replay stored traces/fields/existence/operands rather than call `run_child_row`; first-error/stopped behavior is part of that source algorithm. [C/eval:506–530](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:506), [C/eval:1596–1609](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:1596), [C/eval:3695–3716](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:3695), [C/prepared:449–530](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval/prepared.rs:449). Template construction itself calls the original row client with `TemplateFacts`/thin universe and stores both normal/skipped results; proving the admitted fragment makes that context sufficient is a specific client theorem, not unrestricted provider parametricity. [C/prepared:345–365,377–420](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval/prepared.rs:345).

## Smallest prospective implementation/proof seams

These are proposals, not existing checked results:

1. **Acquisition/authority seam first.** Expose concrete source-bound clients for the actual `SnapshotFacts<Capture>` operations or a narrow snapshot-acquisition result. Prove fresh normalized facts equal prepared facts at the exact full subject/history/schema; establish typed rows/templates and their lookup dependencies; preserve backend history/error behavior. Tie this to actual cache identity and Arc instance checks, not merely state-content equality: cache reuse checks identity; `prepared_for`/retention use `Arc::ptr_eq`; module matching uses full wire identity plus actual borrow-address matching; child application uses epoch pointer identity. [S:1484–1557](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-store/src/store.rs:1484), [C/prepared:28–42,67–93,168–185](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval/prepared.rs:28). Monomorphic wrappers may expose these calls for extraction, but dynamic-dispatch/source/cfg/compiler/Arc/error refinements remain checked obligations, as [T052/T055](/data/repos/behavior-ir-core-033/specs/036-core-transition-feasibility/tasks.md:112) require.
2. **Shared envelope suffix, preserving the original body.** Factor the action-only original code *after obtaining (DecisionRecord,Observed)* into a concrete `finish_resolved_action(module,resolved,record,observed)` client used by both ordinary and prepared invocation. Its original operations are canonical inner text/hash, diagnostics, raw requested invocation, data version, binding facts, envelope and final record. Equal complete native inputs then support congruence for that suffix without passing an irrelevant dynamic provider. [C/invocation:1177–1221](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/invocation.rs:1177), [O/invocation:1139–1183](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-original/crates/behavior-core/src/invocation.rs:1139). Compatibility to the original unpatched call/order/errors must be proved and the refactored real worker rebound. This does **not** prove equality of the two input decisions.
3. **For B05 retain a small source client theorem, not an evaluator oracle.** Bind the selected `finish` path to its actual module/actions/policies; prove reparse equality, capture/binding-check compatibility, select/count equivalence, touched-row execution and untouched template rebind equality in original row order, including first errors, stopped traces, facts, operands, diagnostics, commands and observed read sets. A further extraction-friendly refactor may isolate the unchanged original row-check body behind explicit native row/context inputs; prove that each live/template context supplies the same semantically used original inputs, and prove the trace/observation merge separately. Full `Evaluator` values currently differ (prepared pointer, thin versus complete query universe, world and mutable observation state), so simply wrapping `run_child_row` does not give complete-argument equality. [C/prepared:395–420](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval/prepared.rs:395), [C/prepared:490–519](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval/prepared.rs:490), [C/eval:3719–3740](/var/tmp/behavior-ir-core036-v2/w001/sources/a0003/core-reuse/crates/behavior-core/src/eval.rs:3719). This is narrower than a theorem for all Core clients, but is still mandatory B05 source reasoning. No same-complete-argument use of the **whole** current evaluator is available while `None` and `Some(prepared)` differ.

## B06: inherited validity and original outcomes

Reference execution actually calls `validate_store_snapshot(module,analysis,store,after)`. Promoted views instead materialize state and pass `"Valid"` to the common observation constructor, with method `restricted_finish_preservation`; nonpromoted/fallback execution actually validates. The normative observation currently contains only `original_property_outcomes: {status}`; Ground separately labels the method and says the direct Safety record is not synthesized. Thus inherited validity is intended, and this source fact is **not** a claim that a direct validator ran on the promoted path. It checks module inventory, acquires original `export_seed_at`, inspects export metadata/typed identity/duplicates and dependency predicates, then computes status. `Valid` requires acquired provenance, nonempty dependency/policy context, no findings, successful export hash and validator identity; R/P satisfaction alone does not imply that exact native status.
