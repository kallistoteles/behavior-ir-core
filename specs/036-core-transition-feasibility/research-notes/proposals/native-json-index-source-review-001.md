## Backward compatibility and source-domain conditions

The intended mutable lookup block captures once using `CollectionsFocus.capture`, reads its Option, and closes over that structural focus. `writeValue` preserves a present field on an incompatible None, updates only the present value on Some, and preserves the entire map for an absent focus even on an incompatible Some. It does not delete or insert through an optional mutable lookup. Non-object lookup similarly returns None and an identity reconstruction. These are coherent data totalizations, **provided actual callers prove compatibility**: present focus accepts Some; absent/non-object accepts None. A universal theorem treating arbitrary backward arguments as valid source mutations would be wrong. They need source-map well-formedness, unique keys and a comparison/equality agreement proof; `capture` uses Lean String equality while `captureM` uses the scoped String Ord model. Prove their expected consistency on the admitted byte domain rather than assuming arbitrary dictionaries are lawful. The list-search comparison count need not equal native B-tree search; a pure stable concrete comparator/effect abstraction is required before treating that difference as unobservable. ## Important effect-staging limitation

The source mutates a Null input to `Object(Map::new())` **before** attempting `self.to_owned()` and entry lookup. The draft instead computes `rows := nil` and constructs the outer Object only in the successful returned backward closure. Therefore it does not represent the already-performed Null→Object mutation if key copying, lookup/allocation or another later native operation fails/unwinds. This is a definite difference in modeled staging; whether it affects the chosen observation depends on the separately justified runtime/allocator/panic boundary. For valid successful data equations it need not be a value-result error, but it cannot justify a general performed-error/effect equivalence. Preserve the mutation in an effect/world model or explicitly justify why every applicable failing observation is outside the declared primitive interpretation; do not silently call this a complete native mutable contract. [source mutation order](/var/tmp/behavior-ir-core036-v2/w001/cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/value/index.rs:96).

Likewise merely retaining the to_owned call does not model its allocation/OOM or the occupied branch's disposal of an unused owned key. `.fail .panic` does not model formatted panic contents or unwinding, and the hard-coded ordered gap requires the correct feature-bound JSON backend interpretation. These are unresolved admission/effect obligations, not consequences of valid-data equations.
