## Executable preservation and reusable machinery

There is no source-defined R/GV/B/oracle executable produced by this canary path: extraction uses the worker library and proof checking uses separately supplied analysis/Lean executables. Therefore a fixed four-worker retention shortcut is inappropriate. The exact target executable set is unknown until a later admitted inventory; no names, byte totals, compression ratio, or reclaim amount can be supplied from source alone. Source: [extract argv and worker feature](../../../../experiments/transition-study036/native_accessor_source_canary_v2.py#L590), [proof tools](../../../../experiments/transition-study036/native_accessor_source_canary_v2.py#L790).

The reusable native retention contract retains every current executable-bit ELF beneath the exact leaf, including build-script/proc-macro/shared objects when they meet that predicate. It deduplicates by raw SHA-256, preserves each original relative path in `executables.json`, and allows raw retained references or gzip archives outside the disposable target. `archive_exact` writes exclusively, bounds compressed bytes, checks unchanged source bytes and length, and fully decompresses to check raw SHA-256/length. `verify_retained_inventory` rejects symlinks, missing/duplicate/unlisted current executable paths, source changes, invalid encodings and corrupt archives. This contract does not preserve arbitrary non-ELF executables, non-executable ELF, or generated build source files by itself; a future admission must explicitly reject any additional required artifact under target or preserve it outside target with its own verified references. Sources: [archive_exact](../../../../experiments/transition-study036/native_cache_retention_v2.py#L50), [inventory verifier](../../../../experiments/transition-study036/native_cache_retention_v2.py#L77), [standard inventory/archive loop](../../../../experiments/transition-study036/native_cache_retention_v2.py#L533).

`OwnedCleanup` can cover these exact leaf shapes: they are sufficiently deep beneath the private disposable root. Registration requires verified nonempty retained references outside the target and binds its device/inode. Disposal rechecks identity and references, obtains the work tree lease, respects the unclosed-tree fence, checks its controller descendants for live use, and supports paced removal. It does not establish scientific/evidence read closure, infer the owning attempt, or prove retention completeness; those must be established before registration. Its documented process boundary requires other participating controllers to use the same lease. Sources: [scope and registration](../../../../experiments/transition-study036/owned_cleanup.py#L11), [live-use and disposal checks](../../../../experiments/transition-study036/owned_cleanup.py#L81).
