# Concrete `io::Error` primitive boundary

Research only, 2026-11-20. This is a new **unselected** note, written using the research skill from bounded local primary-source reads. No build, test, probe, download, live-output/process inspection, whole-IR read, protected-artifact access, or implementation/configuration/evidence change was performed. The coordinator supplied actual402 as ongoing; this note makes no claim about that attempt or the receiver/profile-B repair.

## Decision and immediate frontier

**A source-bound generic Error model is implementable, but the preserved opaque declaration is not that model.** Define the source's four logical forms, retain arbitrary custom-error payloads through an explicit runtime object world, and implement the reached constructors/observers. Keep native wrappers, default-method algorithms and their performed effects outside this primitive. Admission still needs a documented relation to the actual native/analysis source domains: the contract explicitly separates justified primitives from unresolved refinements and rejects unsupported opaque stubs. [representation], [boundary]

The genuine dependency's `Step::step`/`twice` return `std::io::Result<usize>`; `twice` forwards the first `Err(error)` unchanged and `run` returns the final state. Its preserved a0401 partial module declares `axiom core.io.error.Error : Type` at line 31 and has `sorry` in `twice.default` at line 54. These are explicit unresolved frontiers, even if a later receiver repair translates the default. The pinned reexports identify this std Result with `core::io::error::{Result,Error}`; replacing its error type by unit or an empty type would change this actual interface. [dependency], [partial], [std-reexport], [alloc-reexport], [core-reexport]

For **this dependency alone**, the smallest sound semantic theorem can be parametric in an arbitrary type parameter `ε` and arbitrary `step` callback: the algorithm only transports its error. That theorem uses no global type axiom and must not assume callbacks always return Ok. It is a generic transport lemma, not yet the concrete `core::io::error::Error` extraction binding; the latter needs the defined type and admission below. The actual State implementation happens to construct only Ok, which does not remove arbitrary Err from the generic trait domain. [dependency], [partial]

## Concrete surface and required source binding

The source owns `Error { repr: Repr }`, with logical variants `Os(RawOsError)`, `Simple(ErrorKind)`, `SimpleMessage(&'static SimpleMessage)` and `Custom(C)`. The physical representation is selected by target pointer width/UEFI cfg, and OS-function storage by atomic/no-IO-statics cfg. A semantic sum may abstract pointer packing only under an explicit representation/ownership interpretation. It cannot erase the variants' different observable behavior. [error-type], [representation], [error-cfg]

## What already exists in Lean, and what does not

The retained a0341 generated `Types.lean:40–84` has a **44-constructor** `core.io.error.ErrorKind`, annotated `@[discriminant isize, rust_type "core::io::error::ErrorKind"]` and bound to the analysis enum at source line 769. The source enum is non-exhaustive to downstream Rust and derives equality/order; its `as_str`/Display tables are concrete source definitions. A reusable pinned enum model can preserve all 44 variants and reject source drift, or reuse the actual generated enum without importing that module's unrelated dependencies. ## Proposed generic observable model

This is a **prospective design**, not implemented or admitted evidence. It follows the source's representation/observer split and the contract's demand for explicit primitive domain/source binding. [representation], [boundary]

1. **Defined types.** Define the pinned `IoErrorKind` enum and a concrete `IoError` inductive with constructors `simple kind`, `staticMessage kind message`, `os rawCode`, `custom kind handle`. Use a defined handle type (e.g. an allocated object-table key with generation/ownership), not `axiom Error : Type`, Unit, Empty, a finite list of feature errors, or a scalar kind/string pair that merges distinct arbitrary payloads. Model RawOsError at the selected source cfg (`usize` on UEFI, `i16` on 16-bit targets, otherwise `i32`). Keep source-owned StudyError and WriterPanicked as separate data types. [representation], [raw-code], [study-error], [writer-panicked]
2. **Explicit runtime world for opaque custom objects.** The world owns arbitrary custom payload objects with dynamic type, identity, source/cause links, mutable state and selected Display/Debug/drop operations. An abstract *interface parameter* for the world is legitimate for generic consumer lemmas; instantiate it with a defined operational object/trace semantics or a separately justified runtime primitive at admission. Do not replace it by a global correctness axiom or a premise saying output observations already agree. Handles preserve the same payload across Err transport, nested boxing, failed downcast and borrow/return; they are not an invented Rust `Eq` instance for Error. The source exposes `get_ref`, `get_mut`, consuming `into_inner`/downcast and source/cause, so a larger future API must retain these distinctions rather than later discovering the representation discarded them. This note does not claim those additional APIs are currently reached. [payload-access], [downcast], [error-display], [custom-drop], [boundary]
3. **Defined observers, with actual effects.** Simple/static/custom `kind` is the stored kind; OS kind invokes the selected OS decoder. `is_interrupted` must follow its own source case split: on OS it calls a separate classifier. Do not assume its equality with `kind == Interrupted` universally from field names; bind/prove the relation for the actual OS implementation. Display dispatches to raw OS formatting plus ` (os error {code})`, custom Display, kind text, or static message. Custom formatting may observe/change world state or fail/panic/diverge; arbitrary custom objects cannot be replaced by a one-time string snapshot. Dropping a custom error invokes destructor callbacks; even an Interrupted error discarded during retry can have effects. [kind], [interrupted], [error-display], [custom-drop]
4. **OS boundary with exact target binding.** Pinned std `from_raw_os_error` supplies `OsFunctions { format_error, decode_error_kind, is_interrupted }`; `last_os_error` reads errno. Atomic storage dispatches these functions through a globally set table. Bind the selected implementation/cfg and actual runtime boundary, or model that table in the world. On the inspected Unix implementation `EINTR` classifies interruption, `EEXIST` maps to AlreadyExists, unknown codes map to Uncategorized, and formatting reaches `strerror_r`. Do not freeze arbitrary platform messages or numeric errno constants from another libc/target. [std-os], [os-table], [unix-os]
5. **Source-owned constructions stay definitions.** Define static constants, simple-kind conversion, reserve-error conversion, and `other::<&'static str>` through the corresponding payload/string allocation interpretation. Allocation/OOM/abort and destructor behavior must be accounted for or explicitly justified as unobservable at the admitted boundary. `BufWriter::with_capacity` uses the infallible Vec allocation API; the OutOfMemory static message in `try_new_with` is a different API and must not be inserted into this path merely because the file contains it. [constants], [from-kind], [reserve-error], [alloc-other], [boxed-string], [buf-capacity]

This split preserves arbitrary errors while allowing ordinary library control flow to inspect only kind/interruption. It does **not** require exposing Rust pointer packing to every theorem. It does require enough world/formatting/ownership semantics wherever the actual observers can distinguish errors. A narrower error-transport theorem may quantify over opaque parameters; the full native delivery/error relation cannot use that theorem as evidence that typed/Display/world bindings have disappeared. [dependency], [error-display], [study-error], [boundary]
