## Smallest principled lowering to investigate

Recognize concrete implementation references in expression generic arguments and dictionary method/parent references, then compute the full **emitted** function/loop/dictionary SCC. For this Value SCC, the smallest plausible lowering is to lambda-lift its recursive dictionary into helpers: `bodyWith d`, `loopWith d`, `serializeWith d`, with the original branch/call/effect order and the original dictionary arguments, replacing only the bound recursive occurrence by `d`. Define the actual dictionary as the least fixed point of `Φ d = Serialize.mk (serializeWith d) proof`; define the actual named method/loop wrappers by specializing those helpers at that dictionary. This preserves the complete cycle via a singleton dictionary fixed point, exploiting the existing NonPos branch rather than pretending the original declarations are acyclic. It is a proposed source-directed extraction transformation, not permission to hand-rewrite generated bodies or replace Value by a model.

Two independent facts must be **proved from the real helper bodies**: for every fixed `d`, `serializeWith d` satisfies the constructor's condition (continuity in the complete Serializer dictionary); and `Φ` is continuous in `d`, hence monotone for its actual CCPO. Existing projection facts from `Fix.cond`, application/fold laws and loop/fixpoint laws are candidate building blocks. Keep every Serializer associated type, implicit binder and actual dictionary instantiation explicit while diagnosing type inference; do not replace the varying dictionary by a discrete domain. The generated constructor requires `Shape.cond`, and `Shape.arr` includes the real continuity clause. [constructor](/var/tmp/behavior-ir-core036-v2/w001/ground-lean-probe/a0346/project/Aeneas/NonPos/Top.lean:338), [negative binder condition](/var/tmp/behavior-ir-core036-v2/w001/ground-lean-probe/a0346/project/Aeneas/NonPos/Top.lean:90), [fixpoint continuity/compatibility](/var/tmp/behavior-ir-core036-v2/w001/ground-lean-probe/a0346/project/Aeneas/NonPos/Top.lean:411).

Merely wrapping the current dictionary and ordinary method functions in Lean `mutual` is not an established solution. In a product fixed point, an arbitrary approximation of the method-function component need not be continuous in Serializer, so `Serialize.mk` cannot obtain its condition from its type alone. A direct mixed mutual lowering must use a lawful continuous/refined function carrier or otherwise derive that invariant for every approximation. The lambda-lifted dictionary operator avoids that particular arbitrary-function premise, but its continuity proofs and preservation of the source recursion semantics still need checking.

The mathematical support is present below the missing extraction feature: NonPos's `Fix` models recursive **dictionary types**, `fold` requires their condition, and `Fix.BotTotal` supplies pointedness and `CCPO` for allowed dictionary shapes. This type fixed point is distinct from the least fixed point defining a recursive dictionary **value**. Lean4.36's `partial_fixpoint` supports mutual cliques by synthesizing each result CCPO, packing component types with `PProd`, replacing recursive applications by packed projections, and proving each operator monotone. It expects every member of a clique to carry the appropriate fixpoint syntax. Thus Lean is not intrinsically limited to singleton recursion, but Aeneas's mixed emitter and the lawful component obligations remain unimplemented here. ## Expected declared control and limit

A prospective small kernel control should retain both recursion paths: dictionary passed to an array-like generic consumer, and dictionary passed to a map-entry method through a loop; the dictionary method must call the actual helper chain. Use a NonPos trait whose method takes the relevant mutually recursive serializer dictionary, explicit associated types, a lawful `Fix.BotTotal`/`CCPO` instance and proved continuity obligations. Require fresh checking of the least-fixpoint equation, projection equations and continuity roots, with transitive axiom inventories excluding `sorryAx` and unapproved assumptions. A wrong-result theorem must fail; an arbitrary opaque method without continuity must still fail constructor packaging. The eventual actual-Value canary must use the complete source-bound body and actual instances, including Number support.

That control would establish the chosen lowering/library mechanism only. It would not establish compiler correspondence, native JSON/collection/runtime adequacy, serializer byte naturality across writer instances, B01–B10, or T059 acceptance. No opaque assumed Value body, desired equivalence premise, arbitrary continuity axiom, deletion of a required dictionary/body, or mere successful parser exit closes this defect.
