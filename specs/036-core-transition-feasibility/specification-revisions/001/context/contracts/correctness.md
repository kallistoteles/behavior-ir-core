# 036 correctness and correspondence contract

## Subject and authority

Reference semantics is the pinned original Core/Safety interpretation, not the optimized implementation or a success flag. The initial native candidate is the exact035 restricted `finish` implementation reconstructed from its immutable sources/patches into a new 036 export. No035 file is edited. A changed036 implementation gets a new source subject and must satisfy the corresponding obligations afresh.

For every admitted finite input `x` and declared enforced environmental premise `E`, the required relation is:

`Obs(Native036(x,E)) = Obs(OriginalCore(x,E))`.

`Obs` includes all eight original fields, exact identities, decisions/refusals, first evaluation error, ordered/multiple commands and normative validation obligations. Safety alone is weaker. Compiler correctness, backend contracts and exclusive writer control are explicit environmental premises; the desired execution/projection/encoding equality cannot be an assumption.

Existing original semantics is not reproved for the full language. Outside the actual selector, equality is established by the same original fallback function on equal full inputs, with equivalent errors/effects. Unknown dependency coverage is affected and cannot be skipped.

## Proof route and stopping rules

1. Bound source/tool availability and inventory the selected call closure, including collections/JSON, Store and host effects. Keep stable native and extraction compiler configuration separate and accounted for.
2. Extract actual source through the pinned Charon/Aeneas tuple; record exact generated files and all opaque/unsupported declarations. No handwritten executable substitute or silently edited generated body is accepted.
3. Freshly check a real-source projection/view lemma plus a deliberately wrong implementation canary. This probe establishes feasibility for that seam only.
4. Extend the native-context relation and prove B01–B10 composition. Reuse035 model laws with fresh type/axiom checks; extend rather than assume omitted native context. Any036 port to the analysis Lean version is new evidence with checked statements, not a relabelled035 check.
5. Independently check expected root types, declared axiom allowlist and the complete transitive proof closure from a fresh build root. Reject `sorryAx`, unsound declarations or an axiom of a required result. Report every justified external premise and its scope.

The 1800 s extraction probe is part of the 5400 s S1 budget. Stop the route if actual dependencies cannot be represented, bindings/cfg/toolchains cannot be justified, or proposed opaque specs merely assert required projection/transition/encoding equality. No other tool or model-only proof is silently substituted. S1 remains unmet; dependent accepted candidates are blocked. Q may still answer the separate canonical-quality question.

### Congruence for unchanged functions

A proof need not establish the internals of a shared canonical encoder/hash solely to show two identical applications agree. It must show the actual same native function is called with equal complete arguments and compatible call/error/effect conditions. A universally quantified function is then an honest congruence boundary. In contrast, a callback named `originalEncoder` plus a model-state equality does not connect native wrapper fields or original bytes. Keep deterministic metadata, captures, original source locations, current history and all ordered data in the relation.

Cryptographic collision/security assumptions are separate from deterministic same-input equality. A new compact hash domain is never a proof that it equals an existing history identity.

1. `invocation`: full original normative content, including decision, diagnostics/evidence where normative and current context.
2. `bundle`: exact optional bundle content, effects and commands.
3. `commit_arguments`: actual original call arguments, not fabricated equivalence-friendly data.
4. `transition_record`: complete required record content and identity.

6. `after_history`: actual confirmed endpoint, including no-content changes to history.

8. `original_property_outcomes`: original-required outcome with honest direct/derived provenance.

The independent unpatched oracle and authored expected semantic facts select the expected parent/result. Candidates cannot choose the expected subject, verifier or comparison projection. Full-value comparison and applicable canonical-byte/hash comparison remain separate explicit checks. Do not drop fields or nested diagnostics to make a comparison pass.

## Buffering contract and native I/O boundary

If diagnosis supports it, the first optional candidate uses a fixed64KiB buffer around the same original serializer. The output still uses create-new, the same exact JSON bytes and newline, explicit successful flush and underlying file `sync_all` before success. Encoding, allocation, writes, flush and synchronization remain inside complete completion. Record all actual errors and preserve incomplete failed artifacts as failed.

Prove that the successful byte stream equals the original stream under the same serializer argument relation, and verify the actual wrapper implements that protocol. Error/fault controls cover create collision, encoding failure where possible, short writes, write failure, flush failure and sync failure. Changing call grouping does not require identical hypothetical failures for omitted syscalls, but operations actually performed retain their error contracts. Partial-write failure never produces a complete-output marker or new imported authority; reconcile an already-applied state before dependent continuation when delivery was uncertain.

A simple byte comparison is conformance, not by itself the general B08 proof. The optional candidate is ineligible if its corresponding proof or full quality result is missing.
